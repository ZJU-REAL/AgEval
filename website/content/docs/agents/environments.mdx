---
title: 环境 kind
description: local / docker / e2b / ssh / daytona，同一条 ACP 链。
---

环境是 job 文档上的独占槽 `environment`。赢家以该名进入服务表；ACP 只 **inject** 这个名字和 `attach_stdio`，不写 `plugin_id: docker`。换 kind 不必改 ACP。`exec` 是同一服务上的一次性命令，不是第二种环境。

| kind | 怎么开 | 真跑条件 |
| --- | --- | --- |
| `local` | 本机目录 | `examples/tau3-airline` 默认 |
| `docker` | 本机容器 | `examples/journeys` 默认 `profiles.yaml` |
| `e2b` | 云 sandbox | `E2B_API_KEY`；`--profiles examples/journeys/profiles.e2b-acp.yaml` |
| `ssh` A | 远端整机 | `AGEVAL_SSH_HOST` / `USER` / `KEY`；journeys 有 dsh / nooa 的 ssh A profiles |
| `ssh` B | 远端已有 image | 同上，且 `image:` 已在远端 |
| `daytona` | 云 sandbox（OCI snapshot） | `DAYTONA_API_KEY`；缺钥 `--probe` `ready: false`。默认 CI 不跑真 Daytona |

```bash
uv run ageval run examples/journeys --task terminal-jsonl-agg
uv run ageval run examples/tau3-airline --task airline-00
uv run ageval run examples/journeys --task terminal-jsonl-agg \
  --profiles examples/journeys/profiles.e2b-acp.yaml --probe
```

缺钥时 `--probe` 应 `ready: false`、`started: false`。ACP 只使用 `attach_stdio`，代码里不应出现 `container_id`。

**ssh A 不支持 live ACP stdio。** 该面上的 journeys profiles 走 dsh / nooa 的 `host.exec`，不是 ACP 长会话。

`environment/setup.sh` 是 environment 末槽，不是独立 phase。gold（`evaluation/`）在 evaluate 才进环境。`--agent` 与 `--profiles` 互斥。`--model` 须配合 `--agent`。

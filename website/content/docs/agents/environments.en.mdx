---
title: Environment kinds
description: local / docker / e2b / ssh / daytona on one ACP chain.
---

The environment is the exclusive job slot `environment`. The winner is exported under that
name. ACP **injects** the name plus `attach_stdio` — never `plugin_id: docker`.
Changing kind does not change ACP. `exec` is a one-shot method on the same service,
not a second environment.

| kind | Opens | To actually run |
| --- | --- | --- |
| `local` | Host directory | Default `examples/tau3-airline` |
| `docker` | Local container | Default `examples/journeys` `profiles.yaml` |
| `e2b` | Cloud sandbox | `E2B_API_KEY`; `--profiles examples/journeys/profiles.e2b-acp.yaml` |
| `ssh` A | Remote machine | `AGEVAL_SSH_HOST` / `USER` / `KEY`; journeys ssh A profiles are dsh / nooa |
| `ssh` B | Remote existing image | Same locators plus `image:` already on the host |
| `daytona` | Cloud sandbox (OCI snapshot) | `DAYTONA_API_KEY`; missing key → `--probe` `ready: false`. Default CI does not run live Daytona |

```bash
uv run ageval run examples/journeys --task terminal-jsonl-agg
uv run ageval run examples/tau3-airline --task airline-00
uv run ageval run examples/journeys --task terminal-jsonl-agg \
  --profiles examples/journeys/profiles.e2b-acp.yaml --probe
```

Missing keys: `--probe` must report `ready: false` and `started: false`. ACP only sees `attach_stdio`.

**ssh A does not support live ACP stdio.** Journeys ssh A profiles use dsh / nooa `host.exec`, not a long ACP session.

`environment/setup.sh` is the last environment slot, not its own phase. Gold (`evaluation/`) enters the scoring host at evaluate. `profiles.yaml` may set `evaluate_host.isolated: true` (Current: `docker`) to start a second scoring box so gold never enters the Agent box; omit it to stay on the run box. `--agent` and `--profiles` are mutually exclusive. `--model` requires `--agent`.

## 推荐配置

```yaml
# Database profiles.yaml
bindings:
  main:
    executor: acp
    extensions:
      - plugin: acp
        options:
          entry: codex
          # reasoning_effort: high   # 可选；必须是该 session 广告的 value
    model: gpt-5.4-mini
    # api_key: ${MY_ENV_NAME}
```

| 字段 | 说明 |
| --- | --- |
| `executor` | coding agent 用 `acp`（不要用已废弃的 `executor: codex` 等） |
| `- plugin: acp` / `options.entry` | **必填**；本机可用 id 以 `bora executors -v` 为准 |
| `options.reasoning_effort` | 可选；广告了 thinking selector 的 entry 走 `set_config_option`。`grok-build` 写进 `grok agent --reasoning-effort … stdio` |
| `model` | 交给该 entry 的模型 |
| `api_key` | 可选；`${ENV_NAME}` locator |
| `base_url` | 可选；字面 URL 或 `${ENV_NAME}` |

不要在 yaml 里写 command / version / install——版本钉在安装与镜像构建。

## 本机就绪

```bash
uv run bora executors -v
```

看 `engine_ready` 与 `acp_entry_ready`。L0 子进程环境只投影 allowlist（`PATH` / `HOME` / `LANG`、entry 声明的 credential 名、binding 的 `api_key` / `base_url`）；宿主里未声明的 token 进不了 entry。

## 运行时切换

```bash
uv run bora run <dataset> --task <id> \
  --set '/parameters/active_profile="main"'
```

父进程只维护**一个** ACP 客户端；各家协议翻译在 entry 进程外完成。操作向说明也见 [换 Agent](/docs/run/switch-agent)。

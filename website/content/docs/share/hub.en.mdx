Hub (`apps/hub`) is the web UI on top of Registry—browse shared packages and run results.

- Dataset list (**Your organizations** / **Explore**), README, task file preview  
- When the package has root `shared/`: Dataset **Shared** tab; Task **Files** header **Local | Shared** (Local default; Attempt evidence does not switch)  
- Large file preview: oversize members return a truncated head with a `truncated` flag (not full download)  
- **Organizations**: members, org packages, shared suite results  
- **Org settings**: invite keys (shown once on create), leave or dissolve  
- Task **Jobs**: open a row when run artifacts were uploaded (layout close to the local Viewer, including trajectory)  
- Dataset version switcher: entitled users see **draft (current)**; everyone else switches among published releases  
- Tasks table: README present, recent job count, last score/status  
- Leaderboard: complete, release-bound suite rows only. Incomplete or draft-bound runs stay on the task Jobs list. Sortable headers. Observational metrics, not suite PASS. Expand a row for **profiles** / **plugin** tabs (secret-free YAML and rehydrate commands; plugins open the marketplace)  
- Plugin detail: L0–L5 **declared-slot** timeline; expand jumps into the in-package file preview. The browser never executes plugin code  
- Signed-in **Home**: jobs you uploaded, orgs, datasets/tasks you can maintain, plugins you uploaded. Signed-out visitors go to sign-in. No publish / upload / release buttons  
- List search sits on the same row as **Your organizations | Explore**; file-tree pane height is stable; trajectory tool-call rows collapse  

- **Sign in with GitHub** (browser OAuth; CLI stays on Device Flow)

## Local dev

```bash
# Terminal A — Registry first (OAuth configured)
export VITE_REGISTRY_PROXY_TARGET=http://127.0.0.1:8700
uv run --extra registry python -m services.registry.app --host 127.0.0.1 --port 8700

# Terminal B
cd apps/hub
pnpm install
pnpm dev   # http://127.0.0.1:5174
```

| Path | Page |
| --- | --- |
| `/home` | Personal home (signed in) |
| `/datasets` | List (Your organizations / Explore) |
| `/datasets/:id` | README · Tasks · Shared (when `shared/` present) · Leaderboard |
| `/datasets/:id/tasks/:task` | README · Files (Local \| Shared) · Jobs |
| `/plugins` | Plugin marketplace |
| `/plugins/:id` | Plugin detail (declared-slot timeline · file preview · CLI install) |
| `/organizations` | Your orgs · Join |
| `/organizations/:orgId` | Overview · Settings |
| `/jobs/...` | Remote Attempt detail (needs uploaded run artifacts) |

Click **Sign in with GitHub** to authenticate. Ops detail: `apps/hub/README.md`, `services/registry/README.md`.

## vs Viewer

| | Viewer | Hub |
| --- | --- | --- |
| Data | Local `.bora/suite-runs/` | Registry |
| Entry | `bora view` | Browser SPA |
| Job artifacts | Local run dirs | Must be uploaded first |

Jobs rows with uploaded run artifacts open detail; others show **Not uploaded**. Trajectories are never invented.

## What to upload so Hub shows it

| You want | Upload | How |
| --- | --- | --- |
| A **Leaderboard** row | A **complete**, **release-bound** suite | `bora publish --draft` then `bora release` (or a direct `bora publish`) → `bora run <database>` **without** `--task` → `upload-suite --suite-run <id>` |
| Task **Jobs** with openable Attempt / trajectory | Suite + **attempt** evidence | `upload-suite --with-attempts`; incomplete / draft-bound suites stay here |
| Archive one Attempt only | `bora results upload --run <run_id>` | May exist in Registry, but **usually not** on Leaderboard |

```bash
# Correct path for Leaderboard
uv run bora run <database> --profiles <profiles.yaml>
uv run bora results upload-suite <database> --suite-run <8-hex> --public --with-attempts

# Not enough for Leaderboard: single-task attempt upload alone
# uv run bora run <database> --task <id>
# uv run bora results upload <database> --run <run_id>
```

Point Hub at the **same** Registry as `bora login` / `~/.bora/credentials` (local dev often `127.0.0.1:8700`). See [Run a Dataset suite](/docs/run/suite).

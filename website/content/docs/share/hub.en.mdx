Hub (`apps/hub`) is the web UI on top of Registry—browse shared packages and run results.

- Dataset list (**Your organizations** / **Explore**), README, task file preview  
- When the package has root `shared/`: Dataset **Shared** tab; Task **Files** header **Local | Shared** (Local default; Attempt evidence does not switch)  
- When profiles declare `overlays:`: Dataset **Overlays** tab; Task **Files** adds an Overlays scope; Leaderboard **profiles** expand shows a Job tree (Dataset package) and/or an Agent tree (`agent_ref` package). One source hides the extra tab; none hides the tree. Not the suite archive.  
- Large file preview: oversize members return a truncated head with a `truncated` flag (not full download)  
- **Organizations**: create from the list page or join with an invite key; members, org datasets / plugins / agents (separate tables), shared suite results  
- **Org settings**: invite keys (shown once on create); owners add members by GitHub login, change role, remove, or transfer ownership; leave or dissolve  
- Task **Jobs**: open a row when run artifacts were uploaded (layout close to the local Viewer, including trajectory)  
- Dataset version switcher: entitled users see **draft (current)**; everyone else switches among published releases. Org owners can flip the current version public/private, delete it, or promote a draft to a release  
- Tasks table: README present, recent job count, last score/status  
- Leaderboard: **Public** (default) lists complete, release-bound suite rows only. **Internal** lists caller-visible incomplete or draft-bound runs in the same table. Sortable headers. Observational metrics, not suite PASS. Expand a row for **profiles** / **plugin** tabs (secret-free YAML and rehydrate commands; plugins open the marketplace). Task Jobs stay as they are.  
- Plugin detail: exclusive / chain **declared-slot** timeline; expand jumps into the in-package file preview. The browser never executes plugin code  
- Official orgs, members of those orgs, and plugins from those orgs show a verified check  
- Public user page lists identity and official orgs only — private memberships stay hidden  
- Org, dataset, plugin, and agent owners can edit the display name (org title, or the leaf after `org/`). The stored package id prefix does not change  
- Signed-in **Home**: jobs you uploaded, orgs, datasets/tasks you can maintain, plugins and agents you uploaded (same official mark and title as the marketplace). Signed-out visitors go to sign-in. No publish / upload / release buttons  
- List search sits on the same row as **Your organizations | Explore**; file-tree pane height is stable; trajectory tool-call rows collapse; steps follow sealed file order; a step shows duration only when `elapsed_ms` is on the sealed row  

- Agent detail: published package (binding + files, including bundled `overlays/`) plus appearances from official public suites that named it with `agent_ref`. Suites run with `--profiles` only stay on the Dataset Leaderboard.

- **Sign in with GitHub** (browser OAuth; CLI stays on Device Flow)

## Local dev

```bash
# Terminal A — Registry first (OAuth configured)
export VITE_REGISTRY_PROXY_TARGET=http://127.0.0.1:8700
uv run --extra registry python -m services.registry.app --host 127.0.0.1 --port 8700

# Terminal B
cd apps/hub
pnpm install
pnpm dev   # http://127.0.0.1:5174
```

| Path | Page |
| --- | --- |
| `/home` | Personal home (signed in) |
| `/datasets` | List (Your organizations / Explore) |
| `/datasets/:id` | README · Tasks · Shared (when `shared/` present) · Overlays (when `overlays:` is declared) · Leaderboard |
| `/datasets/:id/tasks/:task` | README · Files (Local \| Shared \| Overlays) · Jobs |
| `/plugins` | Plugin marketplace |
| `/plugins/:id` | Plugin detail (declared-slot timeline · file preview · CLI install) |
| `/agents` | Published Agent catalog |
| `/agents/:id` | Binding, files, appearances grouped by version |
| `/organizations` | Your orgs · Create / Join · dataset / plugin / agent counts |
| `/organizations/:orgId` | Overview (members · datasets · plugins · agents) · Settings |
| `/users/:login` | Public user profile (official orgs and public datasets / plugins / agents; signed-out OK) |
| `/jobs/...` | Remote Attempt detail (needs uploaded run artifacts) |

Click **Sign in with GitHub** to authenticate. Ops detail: `apps/hub/README.md`, `services/registry/README.md`.

## vs Viewer

| | Viewer | Hub |
| --- | --- | --- |
| Data | Local `.ageval/suite-runs/` | Registry |
| Entry | `ageval view` | Browser SPA |
| Job artifacts | Local run dirs | Must be uploaded first |

Jobs rows with uploaded run artifacts open detail; others show **Not uploaded**. Trajectories are never invented.

## What to upload so Hub shows it

| You want | Upload | How |
| --- | --- | --- |
| A **Public Leaderboard** row | A **complete**, **release-bound** suite | `ageval publish --draft` then `ageval release` (or a direct `ageval publish`) → `ageval run <database>` **without** `--task` → `upload-suite --suite-run <id>` |
| Leaderboard **Internal** | A caller-visible incomplete or draft-bound suite | Same `upload-suite`; does not appear on Public |
| Task **Jobs** with openable Attempt / trajectory | Suite + **attempt** evidence | `upload-suite --with-attempts`; incomplete / draft-bound suites stay here |
| Patch one finished slot on an uploaded suite | New Attempt + suite slot pointer | Local `--resume-suite --replace-slot`, then `upload-suite --suite-run <id> --task <id> [--run <run_id>]`. Hub/Viewer default to current; the version list is `patch N` plus that Attempt’s start time |
| Archive one Attempt only | `ageval results upload --run <run_id>` | May exist in Registry, but **usually not** on Leaderboard |

```bash
# Correct path for Leaderboard
uv run ageval run <database> --profiles <profiles.yaml>
uv run ageval results upload-suite <database> --suite-run <8-hex> --public --with-attempts

# Not enough for Leaderboard: single-task attempt upload alone
# uv run ageval run <database> --task <id>
# uv run ageval results upload <database> --run <run_id>
```

Point Hub at the **same** Registry as `ageval login` / `~/.ageval/credentials` (local dev often `127.0.0.1:8700`). See [Run a Dataset suite](/docs/run/suite).

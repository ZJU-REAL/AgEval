Mechanism plugins extend **how** agents, environments, and trajectories run — not the
dataset `run.py` loop.

## Executor and environment: require the service by name

An executor does not import docker, e2b, ssh, or daytona. It asks for the service named
`environment` and the capabilities it will call. The environment implementation registers
under that name. Lock checks the graph before any invoke.

| | Meaning |
| --- | --- |
| **export** | The environment is the `environment` service |
| **inject** | The agent backend needs `environment` plus `attach_stdio` or `exec` |
| **call** | Protocol only: `attach_stdio` (live session) or `exec` / `upload` (run to completion) |

Switching `environment: docker` to `e2b`, `ssh`, or `daytona` changes the environment winner, not ACP
code. `exec` is a method on that service, not a second service. A host SDK bound to
a parent path does not satisfy this seam. Contract: `docs/design/11`.

## Install (local cache only)

```bash
uv run ageval plugin install plugins/nooa
# or: uv run ageval plugin install plugins/dsh
# or: uv run ageval plugin install plugins/miniswe   # host-loop; bash via environment.exec
# or: uv run ageval plugin install plugins/acp-oneshot  # in-box oneshot ACP pair; exec only
uv run ageval plugin list
```

Install updates `$AGEVAL_HOME/plugins` (default `~/.ageval/plugins`) only. It **never**
rewrites `profiles.yaml`, `ageval.yaml`, or `task.yaml`.

`plugin.yaml` may include `description`: one paragraph Hub shows above Install (CLI). Markdown links (`[text](https://…)`) render there.

## Bind (profiles)

```yaml
format: ageval.profiles/1
environment: local
agent_profiles:
  solver:
    executor: nooa
    extensions:
      - plugin: nooa
        options:
          agent: "lib.agents:JsonlAggAgent"
          method: "run"
```

`executor:` selects the Agent implementation for this profiles file — it does **not** bake. Plugin knobs live on that plugin's `extensions` row. Docker image layers are read by the environment at `host.start()`. ACP `entry` lives on `- plugin: acp` / `options.entry`.

```bash
uv run ageval run examples/datasets/minimal-demo --task terminal-jsonl-agg \
  --profiles examples/datasets/minimal-demo/profiles.nooa.yaml
```

`ageval lock` writes the resolved graph as `extension_bindings`.

```bash
uv run ageval run examples/datasets/minimal-demo --task terminal-jsonl-agg \
  --profiles examples/datasets/minimal-demo/profiles.dsh.yaml --probe
```

`--probe` checks whether this **`environment`** can open here: `host_requires`, Docker daemon (docker), locator **names**. Unsatisfied paths exit non-zero. Skip ≠ pass.

## Recognition ≠ this host can run ≠ image baked

| Stage | Meaning |
| --- | --- |
| **install / list** | Host recognizes the plugin |
| **host-ready** | Declared `host_requires` satisfied |
| **profiles bind** | Job selects that executor / environment |
| **image bake** | docker: `image_layers` present and bake succeeded |

`ageval executors.host_ready` is not “installed” and not “image will bake”. Unlisted installed plugins stay off the Attempt image.

## Relation to ACP

The default coding-agent path remains `executor: acp` + `options.entry` (parent JSON-RPC, needs `attach_stdio`). `acp-oneshot` is the other coding inlet: an in-environment oneshot client+server over `exec` only. Plugins are optional mechanisms; the same `run.py` switches only via profiles. miniswe is a host-loop: the LLM stays on the parent; bash goes only through `host.exec`. Missing `exec` fails at lock.

In-environment `evaluator.py` and layer-C trajectory writes default to `evaluation_runtime` / `trajectory_seal` (no job-field sugar). PASS still binds only in the engine.

---
title: Mechanism plugins
description: Install bora.plugin/1 packages, bind executors, and distinguish Recognition from L1 Ready.
---

Mechanism plugins extend **how** agents, environments, and trajectories run — not the
package harness business loop.

## Install (local cache only)

```bash
uv run bora plugin install plugins/nooa
# or: uv run bora plugin install plugins/dsh
uv run bora plugin list
```

Install updates `$BORA_HOME/plugins` (default `~/.bora/plugins`) only. It **never**
rewrites `profiles.yaml`, `bora.yaml`, or `task.yaml`.

Uninstall:

```bash
uv run bora plugin uninstall nooa
```

## Bind (profiles)

```yaml
# profiles fragment — job binding
bindings:
  solver:
    executor: nooa
    extensions:
      - plugin: nooa
    options:
      agent: "lib.agents:JsonlAggAgent"
      method: "run"
```

`executor:` selects `provide(executor)` only — it does **not** bake or attach
other `on:` slots. Add `extensions` on the same role when L1 needs bake /
trajectory collect (short ids match a path install). ACP-only profiles omit
`extensions`.

Use an alternate profiles file at run time without changing Database ACP defaults:

```bash
uv run bora run examples/journeys --task terminal-jsonl-agg \
  --profiles examples/journeys/profiles.nooa.yaml
# DeepSeek Harness (not ACP):
# uv run bora run examples/journeys --task terminal-jsonl-agg \
#   --profiles examples/journeys/profiles.dsh.yaml
# Optional DSH file-effect policy (plugin-owned options.permission):
# uv run bora run examples/journeys --task terminal-jsonl-agg \
#   --profiles examples/journeys/profiles.dsh.read-only.yaml
```

`dsh` `options.permission` accepts `read-only`, `workspace-write`, or
`danger-full-access`. Omit it to keep unrestricted local bash/fs. Invalid
values fail closed. On the bundled jsonrpc runtime, file-tool writes are
fenced; bash stays local. This is not a BORA isolation claim.

`bora lock` writes the resolved extension graph into `extension_bindings` in the lock summary.

Before a run, probe the same inputs for host feasibility (no Agent invoke, no bake, no lock digest change):

```bash
uv run bora lock examples/journeys --task terminal-jsonl-agg \
  --profiles examples/journeys/profiles.dsh.yaml --probe
# or: uv run bora run … --probe
```

`--probe` branches on **`provider.kind`**: L0 checks declared `host_requires` (for example
`import: deepseek_harness`); L1 does not require a host extra and only checks the bake
file, Docker daemon, and whether credential locator **names** exist. Unsatisfied paths
exit non-zero.

## Recognition ≠ L0 host-ready ≠ L1 bake-declared

| Stage | Meaning |
| --- | --- |
| **install / list** | Host recognizes a provide (Recognition) |
| **L0 host-ready** | Host SPI can be constructed (declared `host_requires` satisfied) |
| **profiles bind** | Job selects that executor |
| **L1 bake-declared** | `image_contribute` + `Dockerfile.bake` exist; bake happens at prepare |

`bora executors.host_ready` means L0 host-ready, not “installed” and not “L1 will bake”.
A successful install does **not** imply the host extra is present, and does **not** imply
the L1 isolated path is ready. Docker L1 tasks need this profile's `extensions` to
select `image_contribute` and a successful bake before the container worker runs
(for example nooa or dsh in-container). Installed plugins that are not listed stay
off the Attempt image.

## Relation to ACP

The default coding-agent path remains `executor: acp` + `options.entry`. Plugins are
**optional** mechanisms beside first-party ACP; the same harness switches only via profiles.

Mechanism contracts live in design docs (`docs/design`); this page does not raise evidence grades.

title: Local results viewer
description: Browse suite runs in the browser — no Registry.
---

After a suite or a single-task run, use Viewer for scores, trajectories, and copyable commands. It reads the **opened** Database only (`.bora/suite-runs/` and `.bora/runs/`) and never talks to Registry.

## Open

```bash
cd apps/viewer && pnpm install && pnpm build && cd ../..
uv run bora view examples/core
# or
uv run bora view examples/core --no-browser --port 8765

# Dev: one command (starts Vite when possible; otherwise prints fallback)
uv run bora view examples/core --dev --port 8765

# Deep-link the run you just finished
uv run bora view examples/core --open /jobs/<id>
```

`bora view --dev` talks to the **same** local API and starts Vite when it can. If it cannot, it prints `pnpm --dir apps/viewer dev`. Two-process contract: API port (default 8765) + UI port (default 5173). Production `bora view` serves `apps/viewer/dist/`.

## Layout

**Jobs → Tasks → Attempt**

| Layer | Content |
| --- | --- |
| Jobs | Local suite runs **and** single-task Attempts (Kind: suite / single). Kind / Source are filters; suite Source lists task ids only |
| Tasks | Per-task status / score. A suite task with one Attempt opens that trial directly |
| Attempt | Outcome, **Timing** (and **Tokens** when present), actors, evidence tabs |

Timing comes from Attempt `phase_timing` (`prepare` / `run` / `evaluate` / `cleanup`); hover bar segments for durations.  
When a sealed `tool_call` row carries `elapsed_ms`, the step header shows that duration. Missing timing is omitted — Viewer does not invent it from file mtimes or the page clock.  
Time / tokens / step duration are **hints**, not PASS. Trajectory is not scoring authority. Each **tool-call** row (and other long rows) can collapse; the observational PASS note has expand-all / collapse-all, matching the Hub Attempt page.

Viewer does **not** talk to Registry — see [Hub](/docs/share/hub). SPA details: `apps/viewer/README.md`.

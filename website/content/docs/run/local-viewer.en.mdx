title: Local results viewer
description: Browse suite runs in the browser — no Registry.
---

After a suite or a single-task run, use Viewer for scores, trajectories, and copyable commands. It reads the **opened** dataset only (`.ageval/suite-runs/` and `.ageval/runs/`) and never talks to Registry.

From the Jobs table you can delete a local Job after a path preview. Deleting a suite always removes the Attempts it references; they do not come back as singles. You cannot delete one Attempt from inside a suite. This is a local erase, not a Registry delete (`ageval results delete` is a different object). The same use case is `ageval jobs delete --local <dataset> --job <id> --yes`.

Pin and notes stay in **this browser** only. They are not written to evidence, lock, or Registry.

## Open

```bash
cd apps/viewer && pnpm install && pnpm build && cd ../..
ageval view examples/datasets/minimal-demo
# or
ageval view examples/datasets/minimal-demo --no-browser --port 8765
# Cached Hub ref (a unique hit does not contact Hub)
ageval view official/demo@0.1.0

# Dev: one command (starts Vite when possible; otherwise prints fallback)
ageval view examples/datasets/minimal-demo --dev --port 8765

# Deep-link the run you just finished
ageval view examples/datasets/minimal-demo --open /jobs/<id>
```

`ageval view --dev` talks to the **same** local API and starts Vite when it can. If it cannot, it prints `pnpm --dir apps/viewer dev`. Two-process contract: API port (default 8765) + UI port (default 5173). Production `ageval view` serves `apps/viewer/dist/`.

## Layout

**Jobs → Tasks → Attempt**

| Layer | Content |
| --- | --- |
| Jobs | Local suite runs **and** single-task Attempts (Kind: suite / single). Kind / Source are filters; suite Source lists task ids only |
| Tasks | Per-task status / score. A suite task with one Attempt opens that Attempt directly |
| Attempt | Outcome, **Timing** (and **Tokens** when present), actors, evidence tabs |

Timing comes from Attempt `phase_timing` (`prepare` / `run` / `evaluate` / `cleanup`); hover bar segments for durations.  
Trajectory steps follow the sealed file order: a thought, then the tools that thought invoked, then the next thought. When a sealed step (thought, `tool_call`, or final assistant) carries `elapsed_ms`, the step header shows that duration. Missing timing is omitted — Viewer does not invent it from file mtimes or the page clock.  
Time / tokens / step duration are **hints**, not PASS. Trajectory is not scoring authority. Each **tool-call** row (and other long rows) can collapse; the observational PASS note has expand-all / collapse-all, matching the Hub Attempt page.

**Verifier:** default is `result.json` plus the `evaluation/` tree. When `evaluation/observation.jsonl` exists (evaluate-phase SDK invoke, LLM-as-judge), that tab reuses the Trajectory step cards. The Agent Trajectory tab still reads only root `trajectory.jsonl`. Observation is not PASS.

Viewer does **not** talk to Registry; remote directories live on the Hub. SPA details: `apps/viewer/README.md`.

## Background

### Problem

`v0.10` 的合同基线可运行一个真实Agent/Environment/Evaluator Trial，但操作者仍需手工修改配置并重复`bora run`。手工循环容易遗漏variant来源、让两次Trial共享resource/evidence、在中途失败后覆盖前一结果，或把retry当作同一Attempt改写。若Campaign直接采用后台queue/durable store，又会在真实reopen/并发需求尚未成立时提前引入`v0.12` authority。

### Current Behavior

- Config Core已接受显式`variant`输入并固定`bora.yaml → Campaign variant → CLI override`顺序，但public application尚无matrix expansion或Campaign identity/summary。
- `bora run`每次只形成一个Run/Trial/Attempt；真实Environment按Attempt-local lifecycle清理，尚未证明多Trial串行不泄漏状态。
- Runtime/Harness/Campaign三类scheduler边界已由design固定：Campaign只调度Trial，不解释Attempt内loop、Tool、branch或Agent fan-out。
- Roadmap内部已实现事实保持不变；本Spec不重新定义`v0.1`–`v0.10`完成态，也不勾选Version Index。

### Goals and Non-goals

- Goal: 增加production CLI `bora campaign`，使用repeatable `--matrix '<JSON Pointer>=<JSON array>'`声明axes；不增加第二份Task Package配置或环境变量实验语义。
- Goal: 在任何Trial启动前完成全部axis解析、allowlist、cartesian expansion、duplicate detection与每variant `load_and_lock`，使非法matrix零Trial fail closed。
- Goal: 每次Campaign创建一个Run和有序Trial集合；每Trial拥有stable `variant_key`、独立`TrialIdentity`、`LockedTaskConfig` digest、Attempt(s)、Environment lifecycle、Result与evidence locator。
- Goal: v0.11固定`max_concurrency=1`，前台顺序运行；后一Trial只有在前一Trial terminal且Provider/Environment cleanup确认安全后才启动。
- Goal: valid evaluator PASS/FAIL和已形成typed Result的runtime/evaluation infrastructure error可记录后继续；admission错误在零Trial前停止，cleanup failure或用户interruption停止后续Trial并发布`incomplete`summary。
- Goal: 可选`--max-infrastructure-attempts 1|2`只对明确retryable infrastructure error生效；retry保留Trial/variant/denominator并创建新Attempt，Evaluator FAIL、policy denial、invalid config与cleanup failure不retry。
- Goal: Campaign summary只保存可比较字段与各Trial Result/evidence引用，采用临时文件+fsync+atomic replace发布；不复制credential、hidden material、raw workspace或完整result tree。
- Non-goal: 本Spec不提供background start/status/cancel、durable queue、跨process coordinator、并发Trial、distributed worker、reopen/resume或crash recovery；只有真实需求成立后由`v0.12`处理。
- Non-goal: 本Spec不实现统计显著性、pass@k、replicate语义、自动搜索、adaptive scheduling、跨Campaign预算或排行榜。
- Non-goal: Campaign不import/executeTask Harness/Evaluator模块、不读取第二份YAML、不修改Harness内部workflow，也不让第三方scheduler成为Run/Trial authority。
- Evidence boundary: Campaign summary与多Trial public path只扩大前台串行调度范围；不自动扩大`isolated`或`real-benchmark-verified`的task/upstream/platform边界。

### Key Insight

Matrix是Config Core的显式输入集合，Campaign是Trial的外层顺序，不是新的配置真相或Attempt内workflow engine。先全量admit再串行execute，可以同时保证非法matrix零副作用、每Trial独立可复盘，以及partial failure不会改写已完成Result。

### Extension Seams

- Matrix input: parser只产生Config variant mappings；Config仍是唯一Task config authority，未来file/UI只需生成相同validated plan而不改变Harness。
- Trial runner: Campaign依赖production single-Trial application protocol，具体Provider/Executor/Environment在composition中注入；Coordinator不按resource/backend/Benchmark分支。

### Matrix Canonicalization and Identity

| Item | v0.11 rule |
| --- | --- |
| Axis syntax | repeatable`--matrix '<RFC 6901 JSON Pointer>=<JSON array>'`；array非空，元素JSON-compatible且通过Config override schema |
| Axis ordering | 先按decoded JSON Pointer UTF-8 byte order排序；同pointer重复直接失败，不merge |
| Value ordering | 每个axis保留CLI JSON array声明顺序；canonical-equal重复值导致duplicate variant失败 |
| Product ordering | 排序后的axes做cartesian product，最后一个axis变化最快；零axis不接受`campaign`命令 |
| Variant mapping | pointer→value immutable map；作为Config `variant`输入，随后再应用repeatable explicit`--set` |
| `plan_digest` | package/task locator、orderedaxes/values、explicit overrides、retry policy与format version的canonical digest；不含时间/host path/secret |
| `variant_key` | `variant-<1-based zero-padded ordinal>-<variant canonical digest prefix>`；相同plan输入可重建 |
| Run/Trial/Attempt | 每次execution新Run；每variant一个新TrialIdentity并绑定variant key/lock digest；retry仅创建同Trial的新Attempt |

Stable variant key用于跨Campaign对齐；Run/Trial/Attempt仍是每次execution的新identity，不能因相同plan digest而复用旧resource或覆盖旧Result。

### Admission and Serial Control Flow

```text
operator → `bora campaign ... --matrix ...`
  → composition builds Campaign use case
  → parse/canonicalize axes → immutable CampaignPlan
  → for every ordered variant:
      Config.load_and_lock(package, task, variant, explicit overrides)
      validate resolved capabilities/resources/plugin/image
  → any admission failure: publish no Run/Trial; exit 2
  → create new Campaign Run + ordered Trial records
  → for Trial 1..N, max_concurrency=1:
      execute production single-Trial path with admitted lock
      optional retryable infrastructure error → new Attempt, same Trial
      wait for terminal Result + confirmed cleanup
      append refs-only TrialSummary
      cleanup failed / interrupt → mark remaining not-started, stop
  → atomically publish complete/incomplete CampaignSummary
  → CLI totals + summary locator + exit code
```

Campaign Coordinator只持有admitted locks、identity、policy与result refs。Task Harness继续拥有Attempt内messages/Tool/branch；Control Plane不importpackage modules或解释action/score业务语义。

### Failure, Retry and Exit Semantics

| Condition | Continue? | Retry? | Summary/exit |
| --- | --- | --- | --- |
| matrix/Config/capability admission failure | 无Trial启动 | 否 | 无Campaign execution；exit 2，typed admission error |
| Evaluator PASS | 是 | 否 | valid Result；Campaign最终是否全pass单列 |
| Evaluator FAIL/低分 | 是 | 否 | valid Result，不是infrastructure failure；最终exit 1 |
| retryable Provider/Agent/Environment/Evaluator infrastructure error | cleanup confirmed后是 | `max-infrastructure-attempts=2`时一次新Attempt | Trial记录orderedAttempts与最终infra/valid Result；若最终error，Campaign exit 2 |
| non-retryable infrastructure error | cleanup confirmed后是 | 否 | Trial error保留；Campaign继续但最终exit 2 |
| cleanup failure/unknown resource state | 否 | 否 | summary `incomplete: cleanup_failed`；remaining not-started；exit 2 |
| SIGINT/cancel | 否 | 否 | 当前Attempt统一cleanup；summary `incomplete: interrupted`；exit 130 |
| summary publish failure | 否 | 否 | per-Trial evidence保留；stderr locator/typed error，exit 2；不发布partial final JSON |

Exit优先级：interrupted=130；否则infrastructure/incomplete=2；否则至少一个valid FAIL=1；全部valid PASS=0。该exit只概括Campaign，不改写各Trial Result。

### Campaign Summary

`CampaignSummary`最少包含：format、campaign/run id、plan digest、ordered axis descriptor、started/finished timestamps、complete flag/reason、`max_concurrency: 1`、retry policy、counts，以及ordered Trial refs。每个Trial ref只含variant key、Trial identity、lock digest、Attempt identity列表、selected final Attempt、status/score/metrics摘要、cleanup state与evidence/result locator。

- summary不复制evaluator raw、Agent messages、DB snapshot、credential、workspace或full lock；locator必须保持Run目录内相对/opaque形式。
- 发布使用same-filesystem temp file、flush+fsync、atomic replace与directory fsync；旧summary（若任何）不被partial bytes覆盖。
- 每次Campaign使用新路径，不覆盖相同plan的旧execution。崩溃前只保证per-Trial evidence和temp cleanup；进程重启reopen/recovery不在v0.11。
- partial failure/interruption仍发布final `complete:false` summary；进程被`SIGKILL`且来不及publish不声称可恢复，v0.12 Research决定是否需要。

## Risks and Mitigations

| Risk | Mitigation |
| --- | --- |
| matrix成为第二份Task配置 | 只接受显式CLI axes并转为Config variant；同一load_and_lock/ResolutionRecord；无matrix env/YAML truth |
| matrix顺序依赖dict/hash/CLI实现 | JSON Pointer canonical排序、value声明顺序、last-axis-fastest规则与property tests |
| invalid后已启动部分Trial | all-variant Config/capability admission在Run/Trial前；start count=0 negative |
| stable key被误当跨run Trial identity | variant key用于对齐；每execution新Run/Trial/Attempt；summary保留两者 |
| 两个Trial共享数据库/credential/workspace | previous cleanup confirmation gate；Attempt-local resource/projection；时间线/state digest/leak scan |
| evaluator FAIL被retry或伪装infra | typed Runtime/Evaluation outcomes；valid FAIL不retry且保留score；summary/exit分栏 |
| retry改写Trial分母或旧Attempt | same Trial/new Attempt lineage；ordered attempts；旧Result/evidence immutable |
| cleanup failure后继续造成污染 | cleanup failure立即stop，remaining not-started，summary incomplete；unknown resource不复用 |
| SIGINT丢失已完成结果或留下child | cancellation bridge+currentAttempt cleanup+atomic incomplete summary；process/resource scan |
| summary复制secret或成为authority | refs-onlyprojection、relative/opaque locators、secret scan；Run/Trial authority仍在Runtime records |
| 前台版本提前引入durable queue/store | filesystem atomic final summary only；无reopen/recovery承诺；v0.12需真实需求+Research |
| 多Trial费用失控 | 固定serial、variant count安全上限、all-admission、用户`B2`授权；无并发或自动大矩阵 |
| 未授权实现 | Decision Summary保持`B2`；未获授权不执行多Trial外部effect、不改production源码 |

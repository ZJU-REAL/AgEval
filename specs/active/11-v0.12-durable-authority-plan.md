## Background

### Problem

`v0.11` 的合同基线可以在一个前台进程中串行完成single Run与Campaign，并在SIGINT时清理当前Attempt。它不承诺启动进程退出后继续运行、另一个CLI查询/取消同一Run、controller崩溃后reopen，或多个control caller并发竞争一个状态转移。仅增加数据库无法自动解决authority：若两个controller都认为自己拥有Run，重复cancel、Result覆盖、失效lease与未fence的旧writer会比无durability更危险。

### Current Behavior

- Run/Trial/Attempt identity、Result/evidence与Provider/Environment cleanup存在于前台execution lifetime；进程退出后没有受支持的control reopen。
- Campaign summary是终态refs-only projection，不是可变ControlStore，不允许从其存在推导background/recovery。
- design与PRD明确durable/reopen默认不做；只有真实跨进程共享、并发竞争、崩溃恢复或后台reopen需求成立后才评估。
- 当前没有用户接受的durable-demand Research结论，因此`B3`阻止实施。本文只能先冻结Roadmap允许的最小候选边界和Research通过后的技术挑战门。

### Goals and Non-goals

- Conditional Goal: 若Research证明需求，支持本地单机、单用户、一个control root内至多一个active background single Run；`bora run --detach`返回durable Run id，另一个CLI可`status`与`cancel`。
- Conditional Goal: SQLite ControlStore成为background control state、lease、cancel request与append-only control event的authority；既有Runtime/evidence仍拥有Attempt事实，Evaluator仍拥有score，ControlStore只保存refs与投影状态。
- Conditional Goal: detached supervisor持有有时限execution lease与monotonic epoch/fencing token；任一时刻只有一个controller可驱动Run，旧controller失去lease后不能提交状态、启动effect或bind Result。
- Conditional Goal: concurrentstatus是只读snapshot；cancel request以request id幂等并原子写入；unknown、不同control root/owner、terminal Run请求fail closed且不改变状态。
- Conditional Goal: 支持四个明确crash windows：effect前可安全claim并开始；Harness运行中只支持reattach/fence后cancel+cleanup，不恢复Harness workflow；Result已bind/cleanup未完可保留Result并完成cleanup；terminal Run只读reopen。
- Conditional Goal: provider/runtime handles只持久化non-secret opaque locator与identity；credential、session token、Docker socket、rawHarness state、Environment admin secret、hidden evaluator material均不进ControlStore。
- Non-goal: 本Spec不支持background Campaign、并发active Runs、remote/multi-user API、跨主机worker、distributed consensus、automatic Harness checkpoint resume、exactly-once external effect、完整crash recovery或global dashboard。
- Non-goal: 本Spec不把SQLite、PID或container存在写成recovery证据；每个支持窗口必须真实kill/reopen并验证，不支持窗口明确terminal/error/cleanup结果。
- Non-goal: 本Spec不改变v0.11 foreground语义；未产生并接受Research时，最接近的viable alternative是继续使用foreground run/Campaign与已有SIGINT cleanup。
- Evidence boundary: 后台control/durability验收不升级`isolated`或`real-benchmark-verified`范围；只证明本Spec声明的单机/single-Run/control/crash windows。

### Key Insight

耐久authority的最小单位不是“把状态写进SQLite”，而是transactional state + exclusive lease + fencing + provider reconciliation + bounded crash semantics。任何旧controller仍能写Result或启动effect的设计都不能称为authority；任何无法恢复Harness workflow的窗口必须明确转为cancel/cleanup，而不是伪装resume。

### User Story

### Extension Seams

- ControlStore: domain/application依赖transactional port；SQLite是首个单机adapter。没有accepted remote need时不实现PostgreSQL/Redis/queue第二store。
- Supervisor launcher: process placement由application adapter提供；CLI不拥有child lifecycle，future service manager只能实现同一ready/lease/exit contract。
- Provider reattach: 只使用Provider公开的opaque identity/inspect/fence/cancel/cleanup；ControlStore不保存Docker client/socket或resource credential。
- Status projection: CLI读取durable snapshot+refs，不成为Runtime/Evaluator truth；future UI只消费同一read-onlyprojection。
- Recovery maturity: 本版只对W0–W3明确行为；Harness checkpoint/resume、background Campaign与cross-host fencing需新的Research/Spec。

### Authority Layers

| Layer | Owns | Must not own |
| --- | --- | --- |
| ControlStore | background Run control identity、state/version、lease/epoch、cancel request、append-only control events、Runtime/Evaluation/Cleanup refs | credential、Docker socket、Harness state、score算法、raw evidence |
| Supervisor | current lease下的execution drive、Provider/Agent/Environment/Evaluation application调用、cancel observation、reconciliation/cleanup | 跨lease写入、Task workflow、Evaluator verdict算法 |
| Runtime/Provider/Environment | Attempt/resource identity、effects、actual process/container/session facts、cleanup | durablecontrol request决策的第二份store |
| Task Harness | Attempt内workflow/messages/Tool/business retry | Run control、lease、credential、final PASS |
| Evaluator/Result binder | score/raw validation/flat Result | control state/lease/cancel |
| CLI/status projection | argv、human/JSON output、exit | 直接SQLite mutation、signal Provider、成为authority |

ControlStore中的`result_ref`只在Result binder成功提交既有evidence后，通过同一control transition记录。Store不得重算或修改score；cleanup completion可在后续transaction追加，而不覆盖Result ref。

### Durable State and Transactions

```text
requested
  → starting
  → running
  → cancel_requested
  → cancelling
  → cleaning_up
  → terminal(succeeded | failed | cancelled | timed_out)

controller loss in nonterminal state
  → reconciling
      → starting/running (W0 only, safe to continue)
      → cancelling/cleaning_up (W1, no Harness resume)
      → cleaning_up (W2, preserve bound Result)
```

每个mutation transaction必须同时：验证owner/control root、expected control version、current state、lease holder/epoch/expiry与fencing token；append一条immutable event；更新projection row/control version；提交或整体回滚。Status只在read transaction读取consistent snapshot，不续lease、不触发reconciliation。

| Record | Minimum fields | Constraints |
| --- | --- | --- |
| `ControlRun` | run id、owner logical id、state/version、created/updated、terminal kind、result/cleanup refs | oneactiveRun partial unique constraint；terminal immutable except allowed cleanup/ref completion |
| `ExecutionLease` | run id、holder id、epoch、fencing token hash、acquired/expiry、heartbeat version | acquire/renew/release CAS；expired旧holder无法commit |
| `CancelRequest` | request id、run id、requester owner、created、status、observed control version | same request id/payload idempotent；conflict fail closed；first accepted transition wins |
| `ControlEvent` | run id、sequence、from/to、kind、actor/epoch、timestamp、sanitized payload digest | append-only contiguous sequence；无secret/rawexception |
| `RuntimeRef` | Attempt/provider/resource/result/evidence opaque locator、phase、actual identity digest | provider token/socket/host path absent；resolve前重验owner/identity |

- SQLite adapter使用WAL、foreign keys、full synchronous或Research接受的等价durability、bounded busy timeout与explicit transactions；目标filesystem不支持安全locks/fsync时preflight fail closed。
- control root directory为0700，DB/WAL/socket/control files为0600并校验当前OS user ownership；symlink、group/world writable、foreign owner与network filesystem拒绝。
- 同一control root最多一个activebackground Run；第二start返回`control_capacity_exceeded`。这不是Campaign/Run并发scheduler。
- lease使用monotonic duration进行本进程判断，durable timestamps用于审计；重启后以store clock policy与Research冻结的grace判定，不能仅信任PID存活。

### Background Start, Status and Cancel Flow

```text
CLI `bora run ... --detach`
  → Config/admission succeeds
  → transaction: create requested Run/control record
  → spawn detached supervisor with run id + control root only
  → supervisor acquires lease/epoch, writes ready event
  → CLI observes durable ready ack, prints run id, exits

supervisor
  → reopens admitted inputs by digest/ref
  → drives normal production single-Run path
  → heartbeat/phase refs under current fence
  → observes durable cancel request at pre-effect boundaries
  → normal/cancel/error → cleanup → terminal transaction → exits

second CLI `status`
  → read-only consistent snapshot + refs → output

second CLI `cancel`
  → transactionally append idempotent cancel request
  → supervisor observes request, transitions cancelling, invokes normal Runtime cancel/cleanup
```

Supervisor argv只含run id/control-root locator与非敏感bootstrap data；locked config、credential与Provider handle从受控store/ref读取，并按既有Runtime重新投影。Task Package代码仍只在Provider runtime中加载；Control Plane不importHarness/Evaluator模块。

### Crash Windows and Reconciliation

| Window | Durable facts | Reopen behavior | Explicitly unsupported |
| --- | --- | --- | --- |
| `W0`：Run admitted，尚无external effect/Provider prepare | request/lock refs/lease event | 新supervisor在lease expiry+fence后可claim并从starting继续 | 双controller、跳过admission、复用旧Attempt |
| `W1`：Provider/resource/Harness已启动，Result未bind | Attempt/provider/resource refs、lastphase、old epoch | 新supervisorinspect exact identities，fence old controller，发cancel并完成cleanup，terminal为controller-loss/cancelled或failed | Harness memory/checkpoint resume、继续Agent loop、自动retry、exactly-once effect |
| `W2`：Result已bind，cleanup未完成 | immutable result/evidence ref、resource refs | 新supervisor保留score/ref，只完成cleanup并写warning/terminal | 重新evaluate、改score、重跑Harness |
| `W3`：terminal | terminal state、Result/Cleanup refs、event sequence | 任意后续CLI只读reopen/status；cancel返回`run_terminal`且零mutation | reopen为running、追加业务effect、修改Result |

- 如果provider identity不存在/mismatch、old controller无法fence或resource state不可判断，Run进入typed`reconciliation_failed`/`manual_cleanup_required`terminal，禁止新Harness/Agent/Evaluator effect与资源复用。
- W1唯一允许的动作是inspect/fence/cancel/cleanup，不恢复workflow。真实Harness checkpoint需求若由Research证明，必须新建后续Spec并设计task/framework-owned checkpoint与Runtime authority边界。
- SIGKILL之外的normal cancel仍走既有Runtime cleanup；crash reconciliation不得绕过writer barrier或让Evaluator读取mutable inputs。

### Failure and Exit Semantics

| Condition | Stable kind / point | Mutation/effect | Result/cleanup |
| --- | --- | --- | --- |
| unsafe control root/SQLite unavailable/corrupt | `control_store_unavailable` / `control_store_unsafe`，preflight | 零Run/Attempt | 不fallback memory store；foreground仍可显式使用 |
| active capacity/lease conflict | `control_capacity_exceeded` / `control_lease_conflict` | loser零external effect | existing Run不变；bounded retry只按Research policy |
| unknown/foreign/terminal control request | `run_unknown` / `run_unauthorized` / `run_terminal` | 零state/effect mutation | version/events/Result不变 |
| duplicate cancel same request | idempotent existing response | 单一cancel transition | 不重复signal/cleanup |
| stale controller/fencing token | `control_fence_stale` | commit与new effect拒绝 | new owner负责reconcile；old process被终止/隔离 |
| supervisor spawn/ready failure | `supervisor_start_failed` / `supervisor_ready_timeout` | Provider零启动或按recorded phase cleanup | durable failed terminal；无第二supervisor |
| W1 controller loss | `controller_lost_running` | 只允许inspect/fence/cancel/cleanup | 无workflow resume/score伪造 |
| W2 cleanup recovery failure | `cleanup_recovery_failed` warning/error | 不重新evaluate | 保留已bind Result，unknown resource non-reusable |
| store commit failure after external fact | `control_commit_failed` | supervisor停止新effect并fence self | reconcile读取Provider/evidence actual facts；不得猜测success |

## Background

### Problem

`v0.2` 只以进程内 stage double 证明 Lifecycle 顺序、取消/超时信号与 cleanup-once 语义。BORA 尚不能把一个 Attempt workload 放到真实运行位置，不能在启动前验证 workdir 与 executable grant，也不能在 timeout/cancel 后终止真实 writer 并报告可复盘的 process outcome。

### Current Behavior

- 当前仓库仍为 `design-only`；[Spec 00](00-core-batch0-and-batch1-plan.md) 与 [Spec 01](01-v0.2-lifecycle-core-plan.md) 尚未实施，当前没有 production Provider 或真实子进程检查点。
- 本 Spec 的合同基线是经用户验收的 `v0.2`：Config 与 Lifecycle 检查点已通过，`bora lock` 仍是唯一 public entrypoint；在 `B1` 解除前不得把该合同基线写成当前实现事实。
- Package Harness、Harness Core、Capability、AgentExecutor、writer barrier、Evaluator 与 Result 均未交付。它们只能由 `tests/` 内显式 helper/double 占位，不能进入 production composition 或被描述为已实现。

### Goals and Non-goals

- Goal: 完整交付 Roadmap `v0.3` 的 Provider L0 工程检查点，使 production `LocalProcessProvider` 能按不可变 launch plan 在 validated Attempt workdir 启动真实本地子进程，捕获有界 stdout/stderr 摘要与结构化 process outcome，并在正常退出、timeout、cancel 和异常后执行幂等 cleanup。
- Goal: timeout/cancel 对 Provider-owned 进程组执行 terminate→bounded wait→kill→bounded wait，确认该组内的测试 writer 已停止；无法确认时 fail closed，保留 primary terminal 并单列 cleanup warning。
- Goal: 每个 outcome 固定记录 `assurance: l0` 与 writer-stop/cleanup 事实，不从本地进程、路径校验或绿色测试推导更高隔离保证。
- Non-goal: 本 Spec 不实现 package Harness、`HarnessContext`、Capability、AgentExecutor、Environment、Artifact materialization、Evaluator、score/metrics、`bora run` 或持久 evidence store。
- Non-goal: 本 Spec 不提供 container、mount/path-view enforcement、network policy、credential projection、UID/GID、cgroup/job-object、VM 或跨 Attempt 隔离；这些保证由 `v0.8` Provider L1 承担。
- Non-goal: 本 Spec 的验收宿主范围仅为通过真实 probe 的 POSIX macOS/Linux；Windows 与其它非 POSIX host 在 spawn 前返回 typed `unsupported_platform`，本版不作支持声明。
- Non-goal: L0 不防止同 UID 子进程发现宿主上本来可访问的路径、socket 或 endpoint，也不物理阻止恶意子进程自行脱离进程组。启动器只做到不主动投影 Docker socket、host-control file descriptor、credential 或未声明环境值。
- Evidence boundary: 本 Spec 完成后证据等级仍为 `design-only`，且不得声称 `runnable-mvp`、`isolated` 或 `real-benchmark-verified`。

### Key Insight

`v0.3` 以 Provider L0 作为完整发版单位。真实执行证据来自 production Provider 启动的 OS 子进程；workload 与未交付阶段仍由测试侧提供。检查点证明的是本地进程 placement、终止和 cleanup，不证明 Harness、Capability、Evaluator 或产品 run 已存在。

### User Story

As a BORA platform maintainer, I can run the Provider L0 application checkpoint against a real local child process, so that I can inspect its validated workdir, exit or termination outcome, `assurance: l0`, writer-stop confirmation, and idempotent cleanup before higher-level runtime surfaces are connected.

### Scope Boundary

- Included: `Provider` / `PreparedRuntime` / `ProcessLaunchPlan` / `ProcessOutcome` 的 L0 contract；canonical package/workspace roots；Provider-owned Attempt workdir；显式 executable grant；direct spawn；新进程组；有界输出捕获；normal exit、spawn error、timeout、cancel、terminate/kill、writer-stop confirmation 与 cleanup-once。
- Deferred to `v0.4`: Attempt-scoped Capability open/close、外部 effect 前授权与 hard ceilings。
- Deferred to `v0.5`: package Harness entrypoint 解析、`HarnessContext` 与正式 `HarnessTerminal`；本 Spec 的 process helper 不升级为 Harness。
- Deferred to `v0.6`: 真实 Agent、Evaluator barrier、flat Result、持久 evidence、公开 `bora run` 与首次 `runnable-mvp` 证据。
- Deferred to `v0.8`: Docker L1、mount/path views、network、credential、hidden material、UID/GID 或同类物理 containment，以及脱离 L0 进程组的 workload containment。
- Deferred to `v0.12`: 后台 control、durable/reopen、跨进程并发 authority 与 crash-window recovery。
- Unsupported in this Spec: Windows / non-POSIX LocalProcessProvider；缺少已接受的近端支持需求，不创建兼容层或虚假 process-tree 保证。

### Extension Seams

- Provider contract: Core 只依赖生命周期与 outcome contract；`v0.3` 实现一个 local-process Adapter，`v0.8` 可接入 Docker Provider 而不让 Lifecycle 按 provider kind 分支。

- Executable grant: Provider 只消费已解析的 immutable grant，不解释 Benchmark/task/Harness 业务；`v0.5` 再由 Harness entrypoint resolver 生产正式 launch plan。

### Control Flow

```text
accepted LockedTaskConfig + AttemptIdentity + test-injected workload declaration
  → application provider checkpoint builds immutable L0 ProcessLaunchPlan
  → Provider.prepare
      → resolve package/workspace roots
      → create Provider-owned Attempt workdir
      → validate workdir containment + executable grant + timing bounds
  → LocalProcessProvider.start
      → direct spawn (`shell=False`) in a new process group
      → bounded concurrent stdout/stderr drain
      → race direct-child exit vs monotonic deadline vs cancellation
  → normal exit or timeout/cancel/error
  → Provider cleanup-once
      → inspect owned process group
      → SIGTERM group → bounded wait
      → if still live: SIGKILL group → bounded wait
      → confirm tracked group gone + sentinel stopped for acceptance probe
      → reap child, close streams, remove Provider-owned workspace
  → identity-bound ProcessOutcome (`assurance: l0`)
  → Lifecycle generic phase fact; remaining unimplemented stages stay test-only
```

无分支把 child exit 0 解释为 Harness completion、Evaluator PASS 或产品成功。Provider 不 import/execute package-local Harness 模块；测试 helper 只是进程生命周期载荷。

### Data Flow

| Data | Source → consumer | Local constraint |
| --- | --- | --- |
| Locked roots与 provider/time limits | accepted lock → application plan builder | 不重读 `bora.yaml`；绝对主机路径只在内存 plan 中使用，不进入公开摘要 |
| `ProcessLaunchPlan` | application/test composition → Provider | immutable、Attempt-bound；`assurance` 只能为 `l0`；非空 direct executable grant、argv、relative workdir、positive timeout/grace/capture limits |
| Package root | Config-resolved reference → Provider | canonicalize + directory check；不作为 cleanup target；L0 不自动 mount 或隐藏其余宿主路径 |
| Attempt workspace/workdir | Provider.prepare → child cwd | Provider 在 canonical workspace root 内创建；拒绝 `..`、absolute relative field、symlink escape 与 root mismatch；launch 前再次验证 |
| Environment / file descriptors | explicit plan → child | 默认不继承宿主 env；只传显式非 secret values；`close_fds=True`、empty `pass_fds`；不投影 Docker socket/control FD，但不声称同 UID 发现防护 |
| stdout/stderr | child pipes → bounded capture → ProcessOutcome | 持续 drain 防止 pipe deadlock；各自 byte cap + truncation marker；probe 不注入 secret；不保存完整宿主环境 |
| process signals/liveness | deadline/cancel + Provider-owned PID/PGID → platform backend | 第一次 terminal reason 胜出；只 signal 当前未终止的 owned group；确认完成后 idempotent cleanup 不再 signal，降低 PID/PGID reuse 风险 |
| `ProcessOutcome` | Provider → Lifecycle/application checkpoint | 保持 runtime terminal、exit/signal、writer-stop 与 cleanup 为独立事实；没有 score/metrics/PASS |

### Reference Data Structures

- `AssuranceLevel`: 本 Spec 只接受 literal `l0`；任何 `l1` / `l2` 请求在 prepare 前返回 unsupported assurance。
- `WorkspacePlan`: immutable Attempt binding、canonical package root、canonical workspace root、Provider-created Attempt directory 与 relative workdir；同时记录哪些路径由 Provider 创建，作为 cleanup allowlist。
- `ExecutableGrant`: canonical executable path、允许的 argv prefix/entry token 与非 secret env key allowlist；缺失、不可执行或 launch request 不匹配时不调用 `subprocess`。
- `ProcessLaunchPlan`: Attempt identity、WorkspacePlan、ExecutableGrant、argv、timeout、TERM/KILL grace、stdout/stderr byte cap；所有数值为有限正数。
- `ProcessOutcome`: Attempt identity、`assurance: l0`、`terminal: exited | failed | timed_out | cancelled`、optional exit code/signal、bounded stream summaries、ordered termination actions、`writer_stop: confirmed | unconfirmed`、cleanup outcome/warning。
- `PreparedLocalRuntime`: Provider-owned ephemeral handle，保存 direct-child handle、PID/PGID、opened streams 与 cleanup state；不可序列化、不可跨 Attempt 复用。

### Process Group and Cleanup Semantics

| Condition | Primary process terminal | Termination / cleanup rule |
| --- | --- | --- |
| Direct child exit 0 | `exited` | drain bounded output；仍检查并终止同组残余 child；确认组消失后 cleanup success |
| Direct child exit nonzero | `failed` | 保存 exit code 与 stderr summary；执行相同 residual-group cleanup，不伪装成 evaluation fail |
| Spawn `OSError` | typed `spawn_failed` preparation/run fact | 无 PID/PGID 时不 signal；清理已创建 workspace；不生成成功 ProcessOutcome |
| Timeout first observed | `timed_out` | signal owned group TERM→wait；仍存活则 KILL→wait；primary terminal 不被 cleanup warning 改写 |
| Cancel first observed | `cancelled` | 与 timeout 相同；与 timeout 竞争时保留 Coordinator/Provider 首次观察到的原因 |
| TERM 后 group 退出 | primary 保持 | 记录 `terminate` action、writer-stop confirmed；不发送 KILL |
| TERM grace 到期 | primary 保持 | 记录 `terminate`,`kill`；KILL 后有界确认 group 与测试 writer 停止 |
| KILL 后仍无法确认 | primary 保持 | `writer_stop: unconfirmed` + cleanup warning；acceptance 失败，禁止把 runtime 标为安全可复用 |
| cleanup 重复调用 | 既有 terminal 保持 | 返回首次 cleanup fact；不得再次 signal、再次删除或追踪已释放 PID/PGID |

L0 writer-stop 只覆盖 Provider 建立并仍拥有的进程组与测试中追踪的同组 writer。主动 `setsid`、double-fork/reparent、同 UID 访问宿主资源与命名空间逃逸不在 L0 保证内；出现这类需求必须使用 `v0.8` L1 containment，不能扩大 `assurance: l0` 的措辞。

### Path Failure Semantics

- Package/workspace root 缺失、非目录或 canonicalization 失败：`invalid_root`，不创建 Attempt workdir，不 spawn。
- Workdir 不是严格相对路径、含 `..`、resolve 后不在 canonical workspace root 内或经过逃逸 symlink：`workdir_outside_workspace`，删除本次已安全创建的空 Attempt dir，不 spawn。
- Executable grant 缺失、target 不存在/不可执行、argv 与 grant 不匹配：`undeclared_executable`，不 spawn。
- cleanup 只操作 `WorkspacePlan.created_paths`；每个 target 删除前重新确认仍位于 canonical workspace root，package root、repository root、调用者 cwd 与宽泛 glob 永不成为删除目标。
- L0 的 pre-spawn validation 不等于 mount/path-view enforcement；同 UID 子进程启动后仍可能读取其宿主权限允许的其它路径，该限制必须进入 outcome/文档而非被路径正向测试掩盖。

## Risks and Mitigations

| Risk | Mitigation |
| --- | --- |
| 只杀 direct child，grandchild writer 继续运行 | 新 session/process group；所有 terminal path 都检查 residual group；TERM→wait→KILL；真实 parent→writer probe + sentinel quiet window |
| child 关闭/重建 session、double-fork 后逃出 L0 group | 明确列为 L0 不保证；不声称 hostile workload containment；需要该保证时使用 `v0.8` L1 |
| stdout/stderr pipe 填满导致 wait/cleanup 卡死 | 并发持续 drain、per-stream byte cap、truncation marker；reader 与 process wait 都受 bounded cleanup 管理 |
| timeout、cancel、normal exit 竞争改写 primary terminal | monotonic first-observed rule；terminal CAS/lock；并发 race tests |
| cleanup 重复 signal 已复用 PID/PGID | PreparedLocalRuntime ownership + cleanup-once；确认 terminal 后清除 active handle；重复 cleanup 只返回旧 fact |
| path 正向测试被误读为 filesystem isolation | 文档/outcome 固定 L0；负向 symlink/workdir 只证明 pre-spawn validation；同 UID host visibility 明确不受保护 |
| ambient credential/control plane 被隐式继承 | explicit minimal env、`close_fds=True`、empty `pass_fds`、no shell；同时明确本版无 credential/mount/network isolation |
| test helper 被误读为 Package Harness | helper 仅在 `tests/helpers/`，production import/composition negative test；输出禁止 HarnessTerminal/PASS/Evaluator 语义 |
| Provider contract 提前冻结 L1 或 Harness 细节 | L0 contract 只含 placement/process/outcome；mount/network/secret/UID/GID 与 Harness launch resolution 由 `v0.5`/`v0.8` 冻结 |

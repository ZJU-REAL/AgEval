## Background

### Problem

`v0.6` 首次让 package Harness 通过 `ctx.agent.invoke` 使用 parent-owned Agent Service，并由独立 Evaluator 形成 Result，但 Harness 作者仍需重复处理 profile 固定、turn 计数、close、Tool lookup、参数校验、hook 顺序、拒绝 Observation 和有限并发。若这些样板各自复制，跨 Attempt session、局部 Tool 次数和 Runtime hard ceiling 容易混淆；若 SDK 接管 Runtime quota、credential、scheduler 或 verdict，又会破坏 Core authority。

### Current Behavior

- 当前仓库仍为 `design-only`；Spec 00–05 尚未实施，`AgentSession`、`ToolSet`、Guard 与 workflow helper 均不存在。
- 本 Spec 的合同基线是经用户验收的 `v0.6`：production `bora run` 已通过真实 Codex、writer barrier 与独立 Evaluator达到限定范围 `runnable-mvp`；在 `B1` 解除前不得把该合同写成当前实现事实。
- `v0.6` Codex Executor 使用 `--ephemeral`，normalized `session_handle` 固定为 null/unsupported。v0.7 的 `AgentSession` 只增加 Attempt/profile/workspace 固定绑定和多次 invoke 样板，不自动获得 provider continuation、resume、reopen 或 durable recovery。

### Goals and Non-goals

- Goal: 完整交付 Roadmap `v0.7`，使 Harness 作者通过独立 `bora-sdk` 使用 Attempt-bound `AgentSession`、`Agent` 薄封装、`ToolSet`、显式 Hook、`AllowList`、`CallLimit` 和最小 async workflow helpers。
- Goal: `AgentSession` 创建时由 parent Agent Service 从 accepted lock 校验 capability scope，并固定当前 Attempt、profile及其 resolved executor/model/options 与 workspace view；后续 invoke 只能引用 opaque binding，不能覆盖profile/workspace/executor/model、跨 Attempt复用、重开closed capability或提高`limits.agent_invocations`。
- Goal: `ToolSet` 在 callable 前完成 tool lookup、input validation 与 declared-order before hooks，在 callable 后归一化 `Observation` 并执行 declared-order after hooks；Guard 拒绝不触发 callable。
- Goal: `AllowList` 与 `CallLimit` 从一次解析的 `ctx.params` typed view 构造。它们只形成单 Harness 进程内的 local Tool soft policy；Runtime Agent/Environment hard ceiling继续在受控 effect 前独立授权或拒绝。
- Goal: `bounded_gather`、`first_success` 与 `collect_results` 只组合当前 Harness event loop 中的 awaitable/value，具有有界取消和收尾，不创建 Run、Trial、Attempt、Provider worker、Campaign scheduler 或 durable state。
- Goal: 提供真实 Codex `AgentSession` public regression 和不消耗模型调用的 deterministic Tool guard public package，并由独立 Evaluator检查 declared artifact。
- Non-goal: 本 Spec 不实现 provider-native continuation/resume。Codex 继续 `--ephemeral`，provider session handle固定null/unsupported；任何非空 handle 或 resume 请求 fail closed。
- Non-goal: 本 Spec 不让 SDK 拥有 credential、Executor routing、Runtime quota、Environment authority、Provider lifecycle、writer barrier、Evaluator 或 final verdict。
- Non-goal: 本 Spec 不实现 L1 filesystem/network/credential/hidden-material 物理隔离；这些属于 `v0.8`，本版证据等级保持限定范围 `runnable-mvp`。
- Non-goal: 本 Spec 不实现第二 AgentExecutor、真实外部 Environment、Campaign 或 durable/reopen authority；分别由 `v0.9`、`v0.10`、`v0.11` 与 `v0.12` 承担。
- Non-goal: 本 Spec 不要求 upstream Framework 改用 BORA helper。已有 Agent object、Tool loop、memory、router 或 scheduler 的 package 可继续绕过对应 SDK helper，只桥接 Runtime Capability。

### Key Insight

SDK session 与 provider continuation 是两个独立概念。`AgentSession` 保存由 parent Runtime确认的 Attempt/profile/workspace逻辑绑定，并把每次真实invoke继续交给同一Agent capability；Codex可以在每次invoke中保持ephemeral且返回null provider handle。`ToolSet`与workflow helper同样只持Harness进程内状态，任何跨进程effect仍穿过Runtime hard ceiling，任何PASS/FAIL仍来自独立Evaluator。

### AgentSession Control Flow

```text
Harness parses typed params once
  → `await AgentSession.open(ctx.agent, profile_id, actor, max_turns)`
      → worker checks current scope/open/deadline and sends bind request
      → parent validates capability scope and fixes Attempt + locked profile(executor/model/options) + workspace view
      → parent stores process-local binding and returns opaque binding id
  → `session.invoke(messages, output_schema)`
      → SDK checks local open/scope/cancel/max_turns
      → worker sends binding id + request; no profile/workspace override
      → parent rechecks binding/open/deadline + Runtime hard ceiling
      → parent routes existing Codex Executor and returns normalized AgentResult
      → provider session handle is null/unsupported
  → explicit/async-context close
      → reject new invokes, settle/cancel owned pending calls, parent discards binding
  → Harness terminal closes every remaining binding again, idempotently
```

- `actor`只进入event/evidence label；它不选择credential、workspace、quota或Executor。
- binding id只在当前Attempt与parent process内有效，不可序列化为跨Attempt capability。worker重放、wrong Attempt、unknown/closed id或payload中的profile/workspace override均在Executor前拒绝。
- `max_turns`是Harness local soft policy。Runtime `limits.agent_invocations`在每次invoke前继续由parent授权；将`max_turns`设得更高不会增加hard ceiling，authorization后failure/cancel仍按v0.6规则不退款。
- 同一逻辑session可在当前Attempt内执行多次独立ephemeral Codexinvoke，但不表示后端保存conversation。Harness必须显式传递所需messages/context；非空provider handle、resume或reopen请求返回typed unsupported error。
- 默认只允许一个session object顺序invoke。若Harness显式并发调用同一session，SDK以process-local lock串行化；并行Agent工作由多个独立session或upstream Framework表达，所有调用仍竞争同一Runtime Attempt hard ceiling。

### AgentSession Reference Types

| Type | Fields / contract | Authority boundary |
| --- | --- | --- |
| `AgentSessionBinding` | opaque `binding_id`、Attempt id、profile id、workspace view id、actor label、open/closed；无credential/resolved executor/model/options/quota/provider token | parent Agent Service从accepted lock创建完整binding record；SDK只持最小只读projection |
| `AgentSession` | binding、scope、local `max_turns`/turn count、invoke/close lock | Harness进程内convenience；不能修改Runtime binding或counter |
| `Agent` | 基于一个`AgentSession`的薄run helper，处理messages/output schema/event与local terminal reason | 无router/team memory/final verdict/scheduler authority |
| `AgentResult` | normalized content、optional typed output、usage observation、executor/model与provider session marker | 沿用v0.6；v0.7 Codex provider session marker固定unsupported/null |

### Tool Call and Hook Ordering

```text
ToolSet.call(ToolCall)
  → resolve known Tool id
  → validate JSON-compatible args through Tool.input_validator
  → before_tool_call hooks in declared order
      → first denial/error short-circuits; callable is not invoked
  → invoke sync or async callable exactly once
      → non-cancellation exception becomes typed error Observation
      → cancellation propagates after owned cleanup
  → normalize value/error into one Observation
  → after_tool_call hooks in declared order, each receiving the Observation
  → emit bounded Tool event and return final Observation
```

| Type | Minimum contract | Failure rule |
| --- | --- | --- |
| `Tool` | stable `tool_id`、description、`InputValidator`、sync/async callable | duplicate/empty id在ToolSet构造时失败 |
| `InputValidator` | `validate(raw: Mapping[str, JSONValue]) -> object` structural protocol；返回传给callable的validated args | validator失败归一化为typed invalid-arguments Observation，不进入hook |
| `ToolCall` | bounded call id、tool id、JSON-compatible args | unknown tool或invalid args在hook/callable前失败且不消费`CallLimit` |
| `HookDecision` | allow或typed deny/error reason | first non-allow停止剩余before hooks与callable |
| `Observation` | call/tool id、`ok | denied | error`、optional value、typed reason；无raw exception/secret | denial、callable error与after-hook error保持可区分 |
| `AllowList` | immutable allowed tool ids | known但未允许的tool在callable前denied |
| `CallLimit` | per-tool non-negative limits、process-localused count、same-loop lock | 在本hook授权时计数；后续callable/error/cancel不退款；超过limit在callable前denied |

- Hook顺序由Harness显式构造，before与after都按声明顺序执行。若较早hook已经改变local state，后续hook拒绝时不回滚；推荐将`AllowList`放在`CallLimit`之前，public example固定此顺序。
- before-hook exception形成typed pre-call error Observation，callable不执行。首个after-hook exception将当前Observation改为typed post-call error并停止剩余after hooks，必须保留`callable_started=true`；这只证明本地callable已进入，不能据此推断外部effect是否发生。
- 共享`CallLimit`对象用同一event loop内的lock仲裁最后额度，适用于受控`asyncio`并发。它没有跨进程原子性、crash reopen或跨Attempt共享语义。
- `AllowList`与`CallLimit`只约束通过同一`ToolSet`路由的调用。Harness直接调用底层callable可以绕过这些对象，因此它们是workflow soft policy，不是权限或安全边界；callable内的外部effect仍必须经过Runtime Capability。
- Tool callable若调用`ctx.environment.action`，local CallLimit先决定是否进入callable，Runtime仍独立检查resource scope与`limits.environment_actions`。Runtime denial可能发生在local Tool已计数之后；SDK不退款，也不能请求提高hard ceiling。
- ToolSet close或Capability closed后调用必须形成typed拒绝。ToolSet不得把closed Runtime Capability重建为可用对象。

### Workflow Helper Boundary

- `bounded_gather(items, limit)`要求`limit > 0`，最多启动`limit`个awaitable，返回顺序与输入顺序一致；首个未处理异常取消并await其余已启动任务，不留下background task。
- `first_success(candidates)`只在显式候选中返回首个满足success predicate的结果；其余owned task按合同取消并await，不做retry、provider fallback或Agent路由。
- `collect_results(results, predicate)`是纯process-local filter/normalizer，不读lock、evidence或Runtime state。
- 三者不创建或命名Run/Trial/Attempt/Invocation，不访问Provider capacity，不持久化checkpoint，不在Harness返回后继续运行。任何Campaign、durable/reopen或跨进程fan-out声称均越出本Spec。

## Risks and Mitigations

| Risk | Mitigation |
| --- | --- |
| opaque BORA binding被误当作Codex/provider resume token | public types分栏；Codex保持ephemeral；provider handle固定null/unsupported；non-null/resume negatives在spawn前失败 |
| SDK持有profile/workspace/quota副本并绕过parent authority | parent从accepted lock创建binding并每次重验；worker只持read-only descriptor；无credential/Executor/remaining grant；hard ceiling regression |
| local max-turn或CallLimit被写成Runtime hard guarantee | 所有文档/类型/测试明确soft/process-local；Runtime pre-effect ceiling独立；高local limit不能提升parent授权 |
| Hook顺序或异常导致denied后仍执行callable | lookup/schema先行；declared-orderbefore chain首个非allow即短路；call counter与`callable_started`证据；pre/post error分型，外部effect仍由Runtime事实判断 |
| concurrent Tool calls争用最后额度产生非确定性 | sharedCallLimit使用same-event-loop lock，count-at-authorization且no-refund；并发last-unit tests |
| workflow helper演化成第二套scheduler | 仅当前event loop、显式输入和bounded cleanup；noRuntime/Campaign/Provider/persistence imports；无orphan task architecture tests |
| public Tool negative被误读为产品失败或伪PASS | CLI/evidence同时显示local denied Observation与independent Evaluator PASS；Harness completed/Tool denied仍不能自行发布verdict |
| SDK示例掩盖L0同UID物理旁路 | 保留`assurance:l0`与v0.8 destination；secret scan只证明未投影/未记录，不声称物理不可达 |
| upstream Framework被迫迁移到BORA对象 | helpers保持可选；upstream Agent/Tool/memory/router/scheduler可绕过，桥接只使用Capability |
| 未验收v0.6上累积实现或产生真实费用 | Decision Summary保持`B1/B2`；依赖验收与明确real-call授权前不开始Phase 0 |

## Background

### Problem

`v0.4` 已在 Control Plane 进程内提供 Attempt-scoped Capability authority，但 Task Package 仍没有可依赖的最小 SDK，也没有受 Provider 管理的 worker 能在独立进程中加载 `harness:run(ctx)`。若 Control Plane 为方便而直接 import package `harness.py`，task-local 模块、全局状态与异常会越过进程边界，破坏 Provider、credential 与 cleanup 所有权。

### Current Behavior

- 当前仓库仍为 `design-only`；Spec 00–03 尚未实施，`sdk/python/src/bora_sdk`、task worker 与 package Harness path 均不存在。
- 本 Spec 的合同基线是经用户验收的 `v0.4`：`bora lock` 可用，Lifecycle、Provider L0 与 Runtime Capability application checkpoints 已验证；在 `B1` 解除前不得把该合同写成当前实现事实。
- Agent、Environment、Evaluator、flat Result 与 `bora run` 均未交付；production composition 对真实 Agent/Environment 继续 fail closed，任何 evaluator module 在本版都不得 import 或执行。

### Goals and Non-goals

- Goal: 完整交付 Roadmap `v0.5`，使 production application use case 通过 L0 Provider 启动 task worker；只有 worker 解析和 import package-local entrypoint，并在 worker 内构造 `bora_sdk.HarnessContext` 与 Attempt-scoped Capability proxy objects。
- Goal: 单独打包 `bora-sdk`，向 Harness 作者提供最小 `HarnessContext`、`HarnessParameterView`、`RunScope`、Capability protocols、`HarnessTerminal`、`publish_json` / `publish_file`；SDK 不依赖 Control Plane 私有模块。
- Goal: parent 只发送一份不含 secret、gold、evaluation input 或完整 lock 的 immutable launch payload；task worker 使用 Runtime-owned代码在本进程内重建 Capability authority/objects，最终只回传一个 typed terminal envelope。
- Goal: 对 locator/path/import/signature/exception/invalid terminal、Capability close、artifact publish、parent timeout/cancel、worker exit/EOF 与 cleanup 提供明确 failure branches。
- Non-goal: 本 Spec 不实现 `AgentSession`、`ToolSet`、Hook、Guard、Context transform 或 workflow helpers；这些属于 `v0.7`。
- Non-goal: 本 Spec 不实现真实 AgentExecutor/Agent Service、真实 Environment、credential/network projection、Evaluator、score/metrics/PASS、evaluator materialization、persistent evidence 或 `bora run`；这些由 `v0.6+` 承担。
- Non-goal: 本 Spec 不设计公开 transport API、Capability RPC、通用 JSONL、跨主机 worker、durable session/reopen 或 compatibility layer。transport 只承载一次 launch 与一次 terminal，是 Runtime-internal implementation detail。
- Evidence boundary: 本 Spec 完成后仍为 `design-only`。真实 L0 worker + example Harness 只证明 package entrypoint/Context/Artifact path，不证明真实 Agent、独立 evaluation、`runnable-mvp` 或隔离。

### Key Insight

公开 Harness API 与 subprocess transport 分层：Harness 只 import `bora_sdk` 并接收普通 `HarnessContext`；worker bootstrap 从 parent 投影的 descriptors 在 child 内构造 Runtime-owned authority与Capability objects。Control Plane 只保留 Run/Lifecycle/Provider authority并处理launch/terminal wire types，从不持有 package module、callable、Harness Python object或运行期Capability request。

### Subprocess Boundary and Ordering

```text
accepted lock + Attempt + PreparedLocalRuntime + Capability descriptors
  → parent projects immutable TaskWorkerLaunchPayload (no secret/gold/evaluation/full lock)
  → parent creates socketpair; Provider starts `python -m bora.adapters.harness_worker`
  → worker Adapter validates payload and constructs worker-local authority + HarnessContext
  → worker alone resolves/imports `<module>:<function>` under package root
  → await `run(ctx)`
      → all Capability checks/receipts remain worker-local
  → worker validates HarnessTerminal and closes local authority/objects
  → worker sends exactly one TaskWorkerTerminalEnvelope and exits
  → parent validates Attempt/session/envelope, closes channel, stops writers, Provider cleanup
```

- Parent 只把 task worker bootstrap module 交给 Provider，不 resolve/import/call package module。task entrypoint callable 与 traceback object 永不跨进程。
- Channel 使用 dedicated inherited socket endpoint；launch payload 不出现在 argv、ambient env 或 stdout。stdout/stderr 保持普通 bounded process evidence，不能承载协议。
- Frame 为 4-byte length prefix + bounded canonical JSON object，唯一顺序是 parent `launch` → worker `terminal`；unknown kind、oversize、invalid schema、wrong Attempt/session、out-of-order 或第二个 terminal 均为 protocol error。本版没有 Capability request、stream multiplexer、plugin message 或公共 transport class。
- Worker Adapter 从 allowlisted descriptors 重建 v0.4 in-process authority；task code只取得SDK surface，不能通过API提高quota、重开closed capability或取得未供应的真实delegate。其同进程L0防旁路限制必须如实记录。

### Packaging and Dependency Direction

| Surface | `v0.5` rule |
| --- | --- |
| Distribution / import | `sdk/python/pyproject.toml` 从 `sdk/python/src/bora_sdk/` 发布 `bora-sdk`；Harness 使用 `import bora_sdk` |

### Launch Payload, Capability Objects and Terminal

| Object | Required content | Forbidden / ownership |
| --- | --- | --- |
| `TaskWorkerLaunchPayload` | format/session、Attempt identity、Provider准备的runtime-visible package view/workspace roots、entrypoint locator、recursive immutable `parameters`、deadline/cancel initial state、declared workspace/artifact/event capability descriptors | 无source package root、完整`LockedTaskConfig`、provider credential、secret value、agent credential/options、evaluation config/input/gold、Docker/control authority；channel FD不序列化进payload |
| Worker `HarnessContext` | `HarnessParameterView`、`RunScope`、worker-local Agent/Environment/Workspace/Artifact/Event objects | 由worker Adapter在local authority上构造和托管；不可pickle/rebind/cross-Attempt；transport不进入public API |
| `HarnessTerminal` | frozen `kind: completed | failed`、optional sanitized task-local reason；constructors `completed()` / `failed(reason)` | 不含 score、PASS、evaluator verdict、cleanup outcome或完整 artifact bytes；Harness return不是 Benchmark Result |
| `TaskWorkerTerminalEnvelope` | format/session、Attempt identity、`returned | bootstrap_failed`、normalized terminal kind/reason、typed error phase/kind/message、bounded worker-local capability/artifact/event receipts | Runtime-internal structural wire type；worker Adapter把SDK `HarnessTerminal`转成字段，parent不import SDK；最多接受一个，并重算declared artifact path/digest后才接受摘要；不含PASS/score/evaluation |

- `HarnessParameterView` 对 recursive frozen parameter tree 提供 dotted-path `require_str/int/float/bool/list/mapping` 与明确 missing/type errors；不暴露 raw mutable mapping或第二份 defaults。
- `RunScope`只允许读取Attempt、deadline、cancel与remaining time；launch后的状态只能由worker monotonic clock或Provider-owned termination signal推进，worker/Harness不能延长deadline或清除cancel。
- Agent/Environment objects由worker-local authority在effect start前返回`capability_unavailable`，不提供permissive local fake。Workspace只表达已声明L0 view/path，不能声称mount隔离。
- `publish_json` 在declared L0 workspace path原子写canonical JSON，`publish_file`只接受scoped relative path；worker-local ArtifactCapability校验logical name/producer/path并登记digest/receipt。terminal envelope只携带bounded receipt summary，parent在worker停止后按launch declarations重算path/digest；`v0.5`不materialize evaluator input。
- Provider为worker staging仅复制locked harness view允许的package文件；loader只接收该view root，`evaluation/`、gold与source package root不进入payload/sys.path。L0同UID代码仍可能主动探测宿主路径，故本版只证明默认投影与loader边界，物理不可见性留`v0.8`。

### Entrypoint, Failure and Cleanup Semantics

- Locator固定为`<module>:<function>`：module只能是dot-separated Python identifiers，function只能是单一identifier；拒绝slash、absolute、relative module与额外colon。
- Worker把module只映射到runtime-visible package view内的`.py`或package`__init__.py`，canonical path必须仍位于view root；不fallback到已安装的同名module。
- Entrypoint必须是一个required positional `ctx`、无其它required参数的`async def`，返回值必须是SDK `HarnessTerminal`。

| Condition | Parent-visible result | Required closure |
| --- | --- | --- |
| Valid `harness:run` returns `HarnessTerminal` | `returned` envelope + separate Harness terminal fact | close worker-local authority/objects → send one envelope → parent close channel → stop worker/writers → verify artifacts → cleanup |
| Locator syntax/path escape/missing module/function | `harness_entrypoint_invalid` / `harness_entrypoint_missing` | worker不执行 task callable；typed envelope if channel healthy；parent cleanup；evaluator不启动 |
| Import exception | `harness_import_failed` with sanitized package-relative context | traceback仅在bounded stderr/internal test evidence；无 Python exception object跨进程；cleanup |
| Non-async/bad signature/non-callable | `harness_signature_invalid` | 不调用 entrypoint；cleanup |
| Harness raises或returns invalid object | `harness_raised` / `harness_terminal_invalid` | close proxies；typed failure envelope；parent固定 Runtime failure并cleanup |
| Agent/Environment unavailable或late Capability call | typed Capability error | delegate/effect不启动；terminal前由 Harness决定返回/raise，terminal后不能改写envelope或artifact receipt |
| Parent timeout/cancel、worker hang/EOF/protocol error | primary `timed_out` / `cancelled` / worker infrastructure failure | parent close channel后由Provider TERM→wait→KILL，确认group stop并cleanup；worker-local authority随进程结束，不等待Evaluator |
| Evaluator sentinel | 本版无 evaluation fact | Control Plane 与worker都不得import/call evaluator；sentinel出现即 acceptance失败 |

## Phase 0: `bora-sdk` packaging、专用 worker transport 与真实 bootstrap probe

### Goal

## Risks and Mitigations

| Risk | Mitigation |
| --- | --- |
| Control Plane直接import task module | parent只处理locator/payload/wire envelope；loader只存在worker；parent `sys.modules` + child PID/import marker负向验收 |
| transport泄漏进Harness API或膨胀成通用RPC | `bora_sdk`只暴露Context/protocol；fixed message kinds + bounded frames；private Runtime modules；无JSONL/plugin message/multiplexing |
| launch payload泄露secret/gold/full lock | allowlisted projection schema + recursive scan；channel-only传输；argv/env/stdout负向检查；evaluator-only字段结构上不存在 |
| parent/worker各持一份mutable authority导致quota分叉 | parent只从accepted lock冻结launch descriptors与limits，不创建并发mutable counter；worker-local Runtime authority是该Harness Attempt的唯一Capability/effect authority，parent只保留Lifecycle/Provider hard stop并在terminal后复核receipts |
| Harness completed被写成PASS | SDK terminal无PASS/score；application/evidence分栏；Evaluator sentinel不执行；`v0.6`独立negative control后才有verdict |
| terminal与late Capability/timeout竞争改写facts | first-terminal arbitration、双侧close、single envelope、late/wrong-Attempt/duplicate frame负向测试 |
| task worker退出但child/background writer残留 | Provider-owned process group；terminal后仍执行stop/writer confirmation/cleanup；timeout升级TERM→KILL |
| SDK反向依赖私有Runtime导致package不可独立使用 | separate wheel isolated install + import graph test；Runtime worker adapters实现SDK protocols，依赖方向单向 |
| L0 workspace/path validation被误读为隔离 | evidence固定`assurance: l0`；同UID旁路明示；物理mount/network/secret/gold隔离留`v0.8` |
| 未验收`v0.4`上累积实现 | Decision Summary保持`B1`；Version Index、baseline suites与用户验收通过前不开始Phase 0 |

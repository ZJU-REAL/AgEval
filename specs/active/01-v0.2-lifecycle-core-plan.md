## Background

### Problem

`v0.1` 只会把 Task Package 锁定为不可变 `LockedTaskConfig`。没有 Lifecycle Core 时，BORA 无法回答一次执行属于哪个 Run / Trial / Attempt、外层阶段按什么顺序推进、失败后由谁进入 cleanup，也无法阻止跨 Attempt 复用阶段结果或把 retry 静默写回旧 Attempt。

### Current Behavior

- 当前仓库仍为 `design-only`；[Spec 00](00-core-batch0-and-batch1-plan.md) 尚未实施，真实 public entrypoint、production composition root 与 `LockedTaskConfig` 均未在代码中出现。
- 本 Spec 的合同基线是经用户验收的 `v0.1`：`bora lock` 可从合法 package 形成确定、无 secret 的 locked summary；在 `B1` 解除前不得把该合同基线写成当前实现事实。
- Provider、package Harness、Capability、Evaluator 与 flat Result 均未交付；不能用 test double 的绿色测试暗示这些边界已可运行。

### Goals and Non-goals

- Goal: 完整交付 Roadmap `v0.2` 的 Lifecycle Core 工程检查点，使 application integration suite 可从一份合法 lock 创建 Run / Trial / Attempt，验证允许的外层顺序、identity scope、独立阶段事实、retry 新 Attempt 以及失败后的单次有界 cleanup。
- Goal: 把取消、wall-time timeout、阶段异常和 cleanup failure 收敛成明确、可测试且不会改写既有事实的 Runtime 语义。
- Non-goal: 本 Spec 不实现或接线真实 Provider、子进程、Harness import/entrypoint、Harness Core、Capability、AgentExecutor、writer barrier、Evaluator、score、flat Result、evidence store、`bora run`、Campaign 或 durable/reopen authority。
- Non-goal: 本 Spec 不新增产品 CLI 命令。`bora lock` 仍是唯一 public entrypoint；lifecycle success 只是一条 application 级工程检查点。
- Evidence boundary: 本 Spec 完成后证据等级仍为 `design-only`。阶段 doubles 只证明 Core 2 编排，不证明 `runnable-mvp`、真实 Agent、物理隔离或独立评测。

### Key Insight

`v0.2` 以 Lifecycle Core 作为完整发版单位。production runtime 提供 identity、状态转移、阶段事实与 cleanup 编排；尚未交付的外部阶段只由 `tests/` 内显式 double 驱动。测试装配必须能证明顺序与失败语义，同时不得进入 CLI composition 或冒充后续 Core 实现。

## Design

> Inherited design: [Core 2：Run、Trial 与 Attempt 生命周期](../../docs/design/01-bora-core.md#24-core-2runtrial-与-attempt-生命周期)、[Run Coordinator](../../docs/design/05-runtime-core.md#82-run-coordinator)、[运行生命周期](../../docs/design/05-runtime-core.md#11-运行生命周期)、[失败语义](../../docs/design/07-budget-evaluation-failure.md#15-失败语义)、[Target Lifecycle](../../ARCHITECTURE.md#lifecycletarget)、[Target module ownership](../../ARCHITECTURE.md#module-ownershiptarget)。
>
> Local delta: 冻结 `v0.2` 的进程内 identity shape、允许转移、generic phase fact、Runtime terminal 与 cleanup 规则，以及 test-only stage double 的装配红线。Provider、Harness、Evaluation 与 Result 的正式接口继续由所属版本冻结。

### Local State Machine

```text
created
  → preparing
      → running_harness
          → harness_terminal
              → sealing_inputs
                  → evaluating
                      → binding_result
                          → cleaning_up
                              → terminal
```

| Branch | `v0.2` rule |
| --- | --- |
| Success | 只允许上图相邻转移；当前 stage 返回同一 Attempt 的 success fact 后才前进 |
| Failure / cancel / timeout | `created` 至 `binding_result` 的任一非终态进入 `cleaning_up`，reason 写入 transition event，不再启动普通 stage |
| Invalid input | 非相邻跳转、重复 stage、terminal reopen 或错误 Attempt identity 在 append event/fact 前 fail closed |
| Cleanup | `cleaning_up → terminal` 只发生一次；`terminal` 无出边 |

`harness_terminal` 只是 Core 2 外层状态名。本版不定义 Harness Core 的正式 `HarnessTerminal` DTO，也不把该状态解释为 PASS。

### Identity and Retry

| Identity | Local shape | Invariant |
| --- | --- | --- |
| `RunIdentity` | immutable typed `run_<uuid4 hex>` | 一次 application lifecycle invocation 创建一个新 Run；不从 task id、路径或时间戳派生 |
| `TrialIdentity` | immutable `trial_<uuid4 hex>` + parent `RunIdentity` + `locked_config_digest` | locked digest 固定后不可替换；跨 Run 复用被拒绝 |
| `AttemptIdentity` | immutable `attempt_<uuid4 hex>` + parent `TrialIdentity` + optional `retry_of_attempt_id` | 首次 Attempt 的 `retry_of` 为空；retry 保留 Trial 但生成全新 Attempt id，旧 Attempt 不变 |

- 默认 ID source 使用 UUIDv4；测试可注入确定 source，但不能改变 parent-binding 校验。
- `AttemptRecord`、`LifecycleEvent` 与 `PhaseFact` 都携带完整 `AttemptIdentity`，写入前与当前 aggregate 做 equality check。
- `retry(previous)` 只接受同一 Trial 的 terminal Attempt，创建带 `retry_of_attempt_id` 的新 Attempt；不复制旧 trace/facts，不修改旧 terminal。
- `v0.2` 不承诺跨进程序号、全局可查询性、持久恢复或并发 retry 仲裁；这些能力归 `v0.12`。

### Failure and Cleanup Semantics

| Condition | Primary Runtime terminal | Phase fact | Cleanup |
| --- | --- | --- | --- |
| 全部 test stages 成功 | `succeeded` | 每阶段独立 `succeeded` | 调用一次；成功 fact |
| prepare / run / seal / evaluation / bind 抛错或返回 failed | `failed` | 仅对应阶段记 typed failure；前序 facts 保留 | 调用一次；不再启动后续普通阶段 |
| cancellation signal observed | `cancelled` | 当前阶段或 boundary 记 `cancelled` | 调用一次 |
| monotonic Attempt deadline 到期 | `timed_out` | 当前阶段或 boundary 记 `timed_out` | 调用一次 |
| cleanup 抛错 | 主 terminal 不变 | cleanup `failed` + sanitized warning | 不重试，不递归 cleanup |
| cleanup 超过 wait budget | 主 terminal 不变 | cleanup `timed_out` + sanitized warning | 取消 cooperative test task 后终止等待；不声称物理 writer 已停止 |

- cleanup guard 第一次进入时标记 `started`；重复异常、cancel 或 timeout 不能触发第二次调用。
- cleanup wait budget 只约束进程内 await。真实 process terminate→wait→kill、writer stop 与资源 teardown 由 `v0.3` 以后证明。
- 错误事实只保存稳定 kind、phase 与无 secret message；cleanup warning 与 Runtime terminal 分列。

### Local Data and Interface Boundaries

| Surface | `v0.2` local delta |
| --- | --- |
| Input | application 只消费已锁定的 `LockedTaskConfig` 与 digest；不重读 `bora.yaml`，不热更新 |
| `IdentityFactory` | `new_run`、`new_trial(run, digest)`、`new_attempt(trial, retry_of?)`；默认 UUIDv4，测试可注入确定 source |
| `LifecycleCoordinator` | 接受 lock、Attempt、internal `LifecycleStages`、cancellation 与正值 cleanup wait budget；返回 immutable `AttemptRecord` |
| `LifecycleStages` | Core 2 内部 seam，只返回 generic `PhaseFact`；不冻结 Provider/Harness/Evaluation 的正式接口 |
| Evidence objects | `LifecycleEvent` 按 sequence append-only；`AttemptRecord` 保存 identity、terminal、trace、phase facts 与可选 cleanup warning，不含 score/metrics/PASS |
| Composition | `run_lifecycle` 显式接收依赖；production composition 不注册 test stage implementation |

## Phase 1: Coordinator、取消/超时与统一 cleanup 收口

### Goal

Coordinator 能按状态机驱动 generic stages，并把阶段故障、取消与 timeout 收敛到只执行一次的有界 cleanup。

### Tasks

- 实现 `LifecycleCoordinator`、`LifecycleStages` 内部 seam、monotonic deadline、`CancellationSignal` 与 cleanup-once guard。
- 在每个普通阶段前后校验 cancel/deadline、Attempt identity 与 phase；只有当前 phase success 才允许前进。
- 保留 prepare、run、seal、evaluate、bind、cleanup 的独立 facts；固定 primary terminal 后 cleanup failure 只能增加 warning。
- 添加完整 success trace、每阶段故障、cancel-before-stage、cancel-during-cooperative-stage、timeout、cleanup raise、cleanup timeout 与 duplicate-trigger 测试。

### Files

- `src/bora/runtime/coordinator.py`
- `src/bora/runtime/cancellation.py`

- `src/bora/runtime/outcomes.py`
- `tests/runtime/test_coordinator.py`

## Phase 2: application 集成检查点与 test-only boundary doubles

### Goal

## Risks and Mitigations

| Risk | Mitigation |
| --- | --- |
| test double 被误读为 Provider/Harness/Evaluator 实现 | double 只在 `tests/doubles/`；production import/composition 负向测试；输出禁止 score/PASS/assurance |
| Core 2 膨胀成后续 Core 或产品竖切 | `src/bora/runtime/` 只含 identity/state/outcome/coordinator/cancellation；真实 I/O、Harness DTO、evaluation Result 与 CLI `run` 全部延期到具名版本 |
| retry 或跨 Attempt fact 改写历史 | identity parent binding、immutable record、append-before validation 与 snapshot regression；retry 总是新 Attempt id |
| cleanup failure 覆盖主失败或未来 score | primary terminal 在 cleanup 前固定；cleanup 单列 fact/warning；测试同时断言主事实与 warning |
| 进程内 timeout 被夸大成物理终止 | 文档和 evidence 明确只证明 bounded await；真实 terminate/kill/writer stop 由 `v0.3` Provider 验收 |
| 状态名提前冻结后续公开 API | `LifecycleStages` 标为 Core 2 内部 seam，stage facts 为 generic internal evidence；Provider/Harness/Evaluation 正式接口由所属版本决定 |
| 未验收 `v0.1` 上累积实现 | Decision Summary 保持 `B1`；Version Index、基线 smoke 和用户验收全部通过前不开始 Phase 0 |

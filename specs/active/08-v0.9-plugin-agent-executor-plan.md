## Background

### Problem

`v0.8` 的合同基线把 first-party Codex Executor 放入受限 L1 Attempt，但单一后端不能证明 `AgentService → AgentExecutor` 是可分发、可替换的稳定边界。如果 registry 通过隐式 import、全局扫描或 runtime fallback 工作，未知/冲突插件可能在 Attempt 后才失败；如果 Harness 根据 `executor == ...` 分支 messages、result 或 session 语义，可比实验与 task workflow 都会绑定具体后端。

### Current Behavior

- 当前 Codex 实现在主仓 adapter 中，production run 尚无 entry point registry 或独立插件 distribution identity。
- Config 可识别声明级 executor kind，但未证明 installed plugin、capability requirement、version/content identity 与实际 Agent Service registry 一致。
- `v0.7` 的 `AgentSession` 合同要求 Attempt/profile/workspace固定，Codex continuation保持unsupported/null；本版必须复用该合同，不得把插件handle、BORA binding与provider resume混成一个ID。
- 本 Spec 只规划新的增量，不回退 `v0.1`–`v0.8` 已实现/已记录的内部事实，也不勾选任何Version Index。

### Goals and Non-goals

- Goal: 主仓定义薄 `AgentExecutor` contract与entry point group `bora.agent_executors`；Application在composition时建立显式registry，Config/Agent Service共享同一只读descriptor集合。
- Goal: `agent_profiles[].executor`只选择kind；Config在Attempt前验证kind唯一、distribution兼容、task所需capability、model/options/workspace/credential/network grant，并把resolved executor identity进入lock digest。
- Goal: 提供独立可安装wheel `bora-executor-openai-responses`，按OpenAI Responses HTTP协议命名；它是第二真实执行机制，不读取Benchmark、task、role或业务action选择逻辑。
- Goal: 同一Task Harness仅通过profile引用在Codex CLI与OpenAI Responses HTTP间切换，并可在同一Attempt中让两个role使用不同后端；Harness只消费统一`AgentResult`与capability descriptor。
- Goal: 每次invocation仍由parent Agent Service绑定Attempt/profile/workspace、执行hard ceiling、选择scoped credential/network grant、归一化result并记录非敏感plugin identity。
- Non-goal: 本 Spec不设远程plugin marketplace、运行中热装/升级、自动下载浮动版本、全局隐式启用、任意plugin patch Core或把entry point当作信任证明。
- Non-goal: 本 Spec不保证两个后端的provider-native session、tool calling、structured output或usage字段天然等价；task requirement必须在Attempt前声明并匹配，不支持即fail closed。
- Non-goal: 本 Spec不新增Environment、真实upstream Benchmark、Campaign、durable session/reopen或background control；分别由`v0.10`–`v0.12`承担。
- Evidence boundary: 第二真实Executor与同Harness公开journey只证明插件/跨后端合同；不自动扩写`isolated`范围，更不形成`real-benchmark-verified`。

### Key Insight

插件发现、配置选型与调用authority是三层独立事实。Entry point只声明“某distribution提供kind”；Config决定本Trial锁定哪个kind/capability；Agent Service在每次invoke前继续执行Attempt scope、hard ceiling与projection。插件只实现执行机制，不能因可安装而获得Run、credential store、workspace grant或Evaluator authority。

### Extension Seams

- Registry: Core只依赖entry point metadata与`ExecutorDescriptor`/factory；第二、第三plugin可外置wheel，不修改Harness或Agent Service分支。
- Protocol adapter: `openai-responses`按HTTP协议与capability工作，不按provider marketing name、Benchmark、task或role决定逻辑。
- Capability negotiation: task/profile声明required features，descriptor声明supported features；Config做集合校验，Harness不读executor kind。
- Credential/network: profile只引用logical grants；projection仍由Runtime/Provider实施，plugin不能扫描host env/filesystem或请求更宽grant。
- Result normalization: plugin raw payload在Adapter内转换为`AgentResult`；Runtime facts与Evaluator result保持独立。

### Discovery, Lock and Invoke Control Flow

```text
clean install
  → distribution metadata exposes `bora.agent_executors/openai-responses`
operator → `bora run ... --set /parameters/models/solver=...`
  → composition builds one immutable executor descriptor registry snapshot
  → Config load_and_lock
      → resolve selected profile
      → require unique installed kind + compatible contract + required features
      → record distribution/version/entry target/content digest in lock
  → L1 Attempt prepare
  → Harness reads only profile id from ctx.params
  → AgentSession binds Attempt + profile + workspace
  → parent Agent Service authorizes invocation hard ceiling
      → selects registry factory by locked kind
      → creates invocation-scoped network/credential projection
      → plugin invoke(normalized request)
      → normalize raw response/error to AgentResult
      → close projection/client and emit facts
  → Harness publishes same declared artifact
  → v0.8 writer barrier + clean evaluator → Result + cleanup
```

Discovery/load只针对用户已安装并由配置引用的plugin。Control Plane不得扫描Task Package寻找entry point，不import/executepackage `harness.py`/`evaluator.py`，也不得因selected plugin失败而选择另一个kind。

### Contract and Descriptor Delta

| Surface | v0.9 frozen delta | Authority boundary |
| --- | --- | --- |
| `ExecutorDescriptor` | kind、contract version、distribution/version、entry target、content digest、supported features、credential/network requirement schema | metadata只描述能力，不授予grant或Attempt scope |
| `AgentInvokeRequest` | Attempt-bound profile ref、messages、optional output schema/tool intent/session capability、deadline/cancel ref | plugin看不到Run store、remaining quota或host credential source |
| `AgentResult` | content、optional structured output、usage observation、executor/model、provider-session capability marker | usage默认观测；final verdict不在此对象 |
| `ExecutorFactory` | 从validated descriptor创建bounded executor/client；不得接收Task identity作逻辑分支 | instance lifetime由Agent Service管理 |
| registry snapshot | kind→validated descriptor/factory，duplicate不可覆盖，selected load失败不可fallback | 仅composition创建；Config与Agent Service共享同一snapshot |
| profile requirement | required features与logical credential/network grants进入lock | unsupported组合在Attempt前失败 |

Feature最小集合固定为`messages`；`json_schema_output`、`tool_intent`与`provider_session`均显式声明。Public example只要求`messages`与可由Adapter可靠提供的`json_schema_output`；任何unsupported feature不允许prompt fallback后伪称等价。

### Plugin Distribution Identity

- Registry按entry point group与name发现descriptor；同kind来自多个distribution时返回`executor_duplicate_kind`，不采用路径顺序或last-wins。
- Contract version不兼容返回`executor_contract_incompatible`；distribution metadata缺失、entry target非法或RECORD不可验证返回`executor_metadata_invalid`。
- Lock记录distribution name/version、entry target、content digest与descriptor capability digest；不记录site-packages绝对路径。
- Editable install只允许开发测试，并在evidence标为`editable`; User Acceptance必须使用build出的wheel与clean isolated install，避免source tree隐式import。
- 运行中不重新扫描registry、不热更新plugin、不接受浮动`latest`或远程download。

### Failure and Cleanup Semantics

| Condition | Stable kind / point | External effect | Cleanup/result |
| --- | --- | --- | --- |
| unknown/duplicate/incompatible/invalid metadata | `executor_unknown` / `executor_duplicate_kind` / `executor_contract_incompatible` / `executor_metadata_invalid`，Config | Attempt前零effect | exit 2，无Run/credential/plugin load |
| selected factory import/init失败 | `executor_plugin_load_failed`，preflight | Harness/Agent invoke前；无fallback | close partial client/projection，Runtime infrastructure error |
| required feature不支持 | `executor_capability_unsatisfied`，Config | Attempt前零effect | 指明profile/feature，不修改Harness |
| credential/network grant缺失 | `executor_projection_unavailable`，preflight | request前零远程调用 | cleanup partial L1 resources，不fallback |
| timeout/cancel/HTTP transport/auth/rate limit | typed invocation error | 可能已开始远程request，事实显式标记 | cancel/closeclient/revoke projection；Harness决定terminal，不能伪装低分 |
| malformed/raw schema mismatch | `executor_response_invalid`，Adapter boundary | response已返回 | raw不直接进入Harness；sanitized error，cleanup继续 |
| forged/cross-Attempt/session feature misuse | existing Agent authority error / `executor_session_unsupported` | plugin invoke count不增加 | binding保持closed/unchanged，无grant |
| evaluator或cleanup failure | 继承v0.8 | 与executor failure分栏 | score、runtime error与cleanup warning互不覆盖 |

## Risks and Mitigations

| Risk | Mitigation |
| --- | --- |
| entry point顺序或duplicate导致非确定后端 | unique kind + duplicate fail-closed；immutable registry snapshot；lock记录distribution/content identity |
| plugin import在Control Plane产生隐式副作用 | metadata先验；仅selected lazy load；用户显式安装/配置；factory bounded close；无Task Package扫描 |
| HTTP协议差异泄漏进Harness | Adapter内request/result normalization；feature negotiation；同Harness source scan与conformance suite |
| unsupported schema/session被prompt fallback伪装支持 | descriptor required/supported集合在Attempt前校验；unsupported stable error；禁止silent fallback |
| plugin获得全局credential/env/network | logical per-profile grant；per-invocation projection；Harness/other plugin cross-read negatives；全树scan |
| plugin绕过Runtime hard ceiling或修改workspace grant | parent先授权并固定binding；contract不暴露counter/grant mutation；last-unit/cross-Attempt tests |
| distribution version相同但内容漂移 | RECORD/content digest进入lock/evidence；User Acceptance用wheel clean install，不用editable source |
| 第二后端只是fixture或fake | public success要求真实Responses-compatible service、真实network/credential与independent Evaluator；fixture只作回归 |
| Harness出现backend-specific branch | typedparams只给profile id；source/architecture test拒绝kind/vendor checks；capability mismatch由Config处理 |
| plugin失败静默降级Codex | selected kind锁定；任何load/preflight/invoke失败typed返回；fallback count为0 |
| 第二Executor被误写成Benchmark或Environment证据 | evidence边界只证明Agent plugin合同；v0.10+Research拥有真实Environment/upstream journey |
| 未授权实现或真实费用 | Decision Summary保持`B2`；未获授权不build/install plugin、不访问外部service、不改production源码 |
